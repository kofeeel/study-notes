# 12. 학습 가이드 — 액션 RPG 설계 패턴 종합

> 스텔라블레이드 분석 결과를 기반으로 한 액션 RPG 개발 설계 패턴 정리.
> 시프트업 지원 및 자체 액션 게임 프로젝트에 적용할 핵심 교훈.

## 1. 전투 시스템 — GAS vs 커스텀

### 핵심 교훈
| 항목 | 낙원 (GAS) | 스텔라블레이드 (커스텀) |
|------|-----------|---------------------|
| 시스템 | GA 195, GE 59, GC 9 | MoveCurve 131, 커스텀 AI 149 |
| 장점 | 표준화, 재사용, 네트워크 지원 | 프레임 단위 제어, 퍼포먼스 |
| 적합 | 멀티플레이어, 다양한 어빌리티 | 싱글 액션, 정밀 타이밍 |

### 적용 체크리스트
- [ ] 프로젝트가 멀티플레이어인가? → GAS 사용
- [ ] 프레임 단위 전투 제어가 필요한가? → 커스텀 고려
- [ ] 콤보/파링/회피가 핵심인가? → MoveCurve 패턴 적용
- [ ] 데이터 드리븐 전투 밸런싱이 필요한가? → CurveFloat/CurveVector 에셋 활용

### MoveCurve 패턴 구현 가이드
```
// 공격 이동 궤적을 CurveFloat로 정의
UPROPERTY(EditAnywhere, Category="Combat")
UCurveFloat* AttackMoveCurve;  // 전진 거리

UPROPERTY(EditAnywhere, Category="Combat")
UCurveFloat* AttackZCurve;     // 높이 변화

// 런타임에 커브 평가
float Alpha = ElapsedTime / Duration;
float ForwardDist = AttackMoveCurve->GetFloatValue(Alpha);
float Height = AttackZCurve->GetFloatValue(Alpha);
```

## 2. AI 시스템 — 대규모 몬스터 AI 관리

### 핵심 교훈
- 117개 Monster AI + 32개 NPC AI = **역할 기반 분화**
- Bot(기계): Attacker/Defense/Range/Supporter — 전투 역할 명확 분리
- 보스: 페이즈별 별도 BT 에셋 (ElderPhase1, ElderPhase2)
- 지역 변형: 같은 몬스터의 영역별 행동 변화

### 적용 체크리스트
- [ ] 몬스터 역할 분류 체계 설계 (Attacker/Defense/Range/Supporter)
- [ ] 보스 페이즈 전환 = BT 교체 방식 검토
- [ ] 지역별 AI 변형 데이터 에셋 설계
- [ ] AIFormation 시스템으로 그룹 전투 관리

## 7. 프로젝트 구조 · 네이밍

| 접두사 | 의미 | 사용처 |
|--------|------|--------|

| `CH_M_` | Character Monster | 몬스터 |
| `CH_NPC_` | Character NPC | NPC |

| `MV_` | Movie | 시네마틱 |
| `WB_` | Widget Blueprint | UI 위젯 |
| `BP_` | Blueprint | 블루프린트 |
| `LV_` | Level | 레벨 |
| `ACC_` | Accessory | 악세서리 |

### 폴더 구조 패턴
```
Content/
├── Art/               ← 아트 에셋 (BG, Character, FX, UI)
├── GameDesign/         ← 게임 디자인 데이터 (Level, Combat, System)
├── Sound/             ← 사운드 (카테고리별 분리)
├── L10N/              ← 로컬라이제이션 (언어별)
├── DLC_{N}/           ← DLC 콘텐츠 (독립 구조)
├── System/            ← 시스템/캐시
└── Local/             ← 로컬 데이터
```

## 9. 시프트업 지원 준비 — 액션 포인트

### 기술 역량 어필 포인트
1. **커스텀 전투 시스템 설계 능력** — GAS에 의존하지 않는 독자적 전투 구현
2. **데이터 드리븐 설계** — MoveCurve, BehaviorTree, 템플릿 기반 시스템
3. **대규모 에셋 관리** — 22만+ 파일 규모의 체계적 폴더 구조
4. **멀티플랫폼** — PS5 햅틱, AMD/NVIDIA 업스케일러, 크로스 입력 지원
5. **Lua 스크립팅 경험** — slua_unreal 활용 가능 어필

### 포트폴리오 프로젝트 제안
1. **소규모 액션 데모** — EVE 스타일 3인칭 콤보 전투
2. **보스 AI 시스템** — 페이즈 전환 + 패턴 분기 BehaviorTree
3. **MoveCurve 기반 전투** — CurveFloat로 공격 궤적 제어
4. **코스튬/악세서리** — KawaiiPhysics 기반 물리 장신구
5. **시네마틱 파이프라인** — Level Sequence + 대화 카메라 템플릿

## 10. 언리얼 페스트 2024 — 시프트업 공식 기술 (핵심 요약)

> 출처: [[raw/[언리얼 페스트 2024] 스텔라 블레이드_ 화려함과 성능의 조화 – 전투 시스템 및 최적화 전략]]

에셋 분석만으로는 알 수 없었던 **내부 구현 디테일**. 면접/포트폴리오에 반드시 반영할 것.

### 10-1. 쇼메이커(Showmaker) — 자체 연출 툴
- Seq_ 64,877개 에셋의 정체 = 레벨 시퀀스 제외 모든 연출을 담당하는 자체 툴
- 애니메이션/블루프린트에 **비의존적** 연출 재생
- 기획/아트/사운드 파트가 **한 툴에서 협업**
- → **어필**: "연출 툴 자체 제작 경험" 또는 "데이터 드리븐 연출 시스템 이해"

### 10-2. 타격 판정 — 이중 방식 + 보간
| 무기 유형 | 판정 방식 | 핵심 기술 |
|----------|----------|----------|
| 검 (얇은 무기) | 트라이앵글 (소켓 삼각형) | 프레임간 보간으로 궤적 누락 방지 |
| 몸통/대형 무기 | 히트박스 스윕 트레이스 | 셰이프 컴포넌트 + 이전 트랜스폼 |
- **경사지 보정**: Look-at IK로 상체가 적 중점을 바라봄
- → **구현 연습**: `FHitResult`, `SweepMultiByChannel`, `GetSocketTransform` 활용

### 10-3. 타격감 3층 구조
```
Layer 3: Vertex Shake (WPO) — 피격 부위 버텍스를 물리적으로 눌러줌
Layer 2: Bone Shake        — 주요 본 위치/회전 비틀기
Layer 1: Hit Stop          — 애니메이션 일시 정지 + IK 밀착 보정
```
- → **구현 연습**: `UAnimInstance::Montage_Pause`, 커스텀 AnimNode, 머티리얼 WPO

### 10-4. 실시간 절단 (Dismemberment)
ProceduralMesh + VertexSkinning 조합:
1. 절단 본의 스킨 웨이트 버텍스 → ProceduralMesh 생성
2. 나머지 SkeletalMesh는 버텍스 컬러 마스킹으로 숨김
3. 임펄스 → 비산 연출
4. 레그돌 트랜스폼 기반 스키닝 → 절단면 자연 연결
- → **구현 연습**: `UProceduralMeshComponent`, `GetRefVertexBoneWeights`

### 10-5. AI 포지셔닝 — 55×55 셀 그리드
- 플레이어 중심 셀 기반 시스템 (EQS 대신 커스텀)
- **Theta\* 알고리즘** → 부드러운 경로
- 대형 몬스터 = 장애물 파괴, 소형 = 우회
- 우선순위 기반 밀어내기 (스킬>체형>속도)
- → **구현 연습**: Grid 기반 Pathfinding, 충돌 우선순위 시스템

### 10-6. CPU 최적화 (PS5 60FPS)
| 기법 | Before | After | 감소율 |
|------|--------|-------|-------|
| 캐릭터 무브먼트 병렬화 | 2.8ms | 1.0ms | **64%** |
| PhysX 본 제외 | RigidDynamic 과다 | 캡슐 대체 | 대기시간 제거 |
| 루트 모션 병렬화 | 게임스레드 블로킹 | 3ds Max 사전 추출 | 멀티스레드 |
| 파티클 프레임 분산 | 스파이크 | 1ms/프레임 제한 | 스파이크 제거 |

**핵심**: 엔진 내부 로직(CharacterMovementComponent)을 과감하게 병렬화. 매니저 클래스로 Move 로직 분리 후 스레드세이프하지 않은 부분만 게임스레드에서 지연 처리.
- → **어필**: "엔진 내부 수정 경험", "멀티스레드 프로그래밍", "프로파일링 기반 최적화"

### 10-7. 면접 대비 핵심 질문 예상
1. "GAS를 사용하지 않은 이유는?" → 프레임 단위 제어 + 싱글플레이어 + 쇼메이커 통합
2. "타격 판정 방식은?" → 트라이앵글 + 스윕 이중 방식 + 트랜스폼 보간
3. "60FPS 달성 전략은?" → 프레임 분산 + 무브먼트 병렬화 + PhysX 최적화
4. "AI 이동 시스템은?" → 55×55 셀 그리드 + Theta* + 우선순위 밀어내기
5. "절단 시스템 구현은?" → ProceduralMesh + 버텍스 스키닝 + 스레드 분리
