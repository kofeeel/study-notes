# 14. IF 액션게임 — 스텔라블레이드 레퍼런스 스카우팅

> **목적:** SB(스텔라블레이드)의 전투 디자인 중 IF 액션게임에 가져갈 것을 선별한다.
> **시점:** 본편 + DLC 클리어, 디컴파일 분석 완료 (2026).
> **제약:** 개발자 2명, 전담 아티스트 없음, UE5.7 + GAS, Steam Deck OLED 검증 목표.

---

## 1. SB 전투를 한 줄로 요약하면

> **3개의 스탯(HP·Shield·Balance), 4개의 색상 신호(빨·노·파·보), 그리고 방어 성공이 공격을 해금하는 다중 후속 상태** — 이 세 가지가 서로의 존재 이유가 되어 맞물리는 구조.

이게 SB가 다른 액션게임과 다른 이유다. "스킬이 화려하다", "타격감이 좋다"는 결과일 뿐, 디자인의 핵심은 위 인터록(interlock)이다. 우리가 가져와야 할 것도 여기다.

---

## 2. 우리에게 의미 있는 SB의 디자인 선택

각 항목은 **Adopt / Adapt / Skip** 으로 판정한다.

- **Adopt**: 거의 그대로 가져온다.
- **Adapt**: 핵심 아이디어만 가져오고, 우리 규모에 맞게 축소한다.
- **Skip**: ROI가 맞지 않아 제외한다.

### 2.1 코어 메커닉 — 메커닉만으로 깊이를 만든 부분 (대부분 Adopt)

이 영역이 SB의 진짜 가치다. **아트 부담이 거의 없고**, 우리 팀 규모에서도 충분히 구현 가능하다. 가능한 한 그대로 가져오는 게 좋다.

**3스탯 삼각관계 (HP / Shield / Balance) — ✅ Adopt**
플레이어와 적이 동일한 스탯 구조를 공유한다. 비대칭 게임이 아니라 "거울 시스템"이라서 디자인 부담이 작다. Shield는 1차 방어막, Balance는 그로기 트리거, HP는 최종 생존선이고, 각 스탯이 다른 스탯의 공략 도구가 된다(패링 → Balance↓ → 그로기 → HP 큰 피해). 이 단일 구조가 SB 전투의 모든 전략적 깊이를 떠받친다.

**색상 신호 1:1 대응 (빨/노/파/보) — ✅ Adopt**
적의 공격에 색이 붙는 순간 대응법이 단 하나로 강제된다. 가위바위보 구조라 학습이 직관적이다. 구현 비용도 작다 — 머티리얼 + Niagara 이펙트 정도면 충분하고, 아트 부담이 거의 없다. 단, IF에선 **3색으로 시작**해서 후반에 한 색을 추가하는 점진 확장이 안전하다. 색마다 전용 회피 동작이 필요하므로 콘텐츠 부담이 곱셈으로 늘어난다는 점을 잊지 말 것.

**연속 가드 무페널티 — ✅ Adopt**
SB의 가장 영리한 결정. 가드를 연타해도 스태미나나 가드 크래시 같은 페널티가 없다. 소울라이크의 진입장벽을 의도적으로 낮추고, 대신 균형 게이지의 보상으로 차등화한다. "막다가 죽는" 좌절을 없애주는 게 핵심이라, 우리도 그대로 따라간다.

**방어 성공 → 후속 콤보 해금 — ✅ Adopt (축소)**
SB는 다섯 종류(패링/닷지/블링크/리펄스/공중) 후속 상태를 가진다. IF는 **3종(패링/닷지/공중)** 으로 시작하는 게 적정하다. 블링크와 리펄스는 색상 신호와 1:1 매칭이라 모션 작업량이 곱셈으로 늘어난다. 검증 후 단계적으로 추가.

**관대한 판정 윈도우 — ✅ Adopt**
SB는 12~13프레임의 기본 윈도우를 스킬로 확장한다(이 수치는 디컴파일 교차검증 필요). 핵심은 **숫자가 아니라 "스킬로 늘려주는 정책"**. 초보와 숙련자 모두 만족하는 슬라이딩 난이도가 만들어진다.

**타깃 락온 — ✅ Adopt (저비용)**
UE5의 Gameplay Targeting System으로 거의 무료에 가까운 비용으로 구현 가능하다. 카메라 이탈 방지는 스타일리시 액션의 기본 요건이라 빼면 안 된다.

---

### 2.2 연출과 피드백 — 가져오되 축소 (대부분 Adapt)

SB의 화려함은 전담 팀이 만들어낸 결과다. 우리는 같은 효과를 더 작은 비용으로 만들어야 한다.

**3층 타격감 (HitStop + BoneShake + VertexShake) — 🟡 Adapt**
**HitStop은 필수다.** 거의 비용 없이 타격감의 80%를 만든다. BoneShake와 VertexShake는 **핵심 무기 1~2개에만 적용**한다. 모든 적/무기에 깔면 작업량이 폭발한다.

**이중 타격 판정 (Triangle + Sweep) — 🟡 Adapt**
검의 정밀 검출이 절대적으로 필요한 상황이 아니라면 **Sweep만으로 충분**하다. 시작은 Sweep으로 가고, 검 정밀도 이슈가 실제로 보이면 그때 Triangle을 도입한다.

**MoveCurve 데이터 드리븐 — 🟡 Adapt**
SB는 131개의 MoveCurve로 공격/넉백/그랩 궤적을 데이터로 관리한다. IF에선 **GAS의 GA + UCurveTable + SetByCaller** 조합으로 동등 효과를 낸다(자세한 매핑은 [[13-UE5-GAS-설계안]] B-1 참조). 분량은 **30~50개** 정도면 충분. 핵심은 "디자이너가 코드 수정 없이 전투 감각을 조절할 수 있다"는 정책이지, 갯수가 아니다.

---

### 2.3 콘텐츠와 자원 시스템 — 우리에겐 사치 (대부분 Skip)

SB가 풀팀으로 만들어낸 콘텐츠 분량은 우리가 흉내 낼 수 없다. 흉내 내려 하면 프로젝트가 망한다.

**5스킬트리 + 엑소스파인 + 기어 + 드론 + 소모품 — ❌ Skip**
IF는 **단일 스킬셋 + 1~2개 빌드 변수**로 시작한다. 빌드 다양성은 "장비 종류"가 아니라 "스킬 슬롯의 트레이드오프"에서 만든다. 적은 수의 슬롯에 어떤 스킬을 넣느냐로 빌드가 갈리는 구조.

**베타/버스트/타키 — 3중 스킬 자원 — ❌ Skip**
UI 슬롯, 게이지 디자인, 밸런싱이 모두 곱셈으로 늘어난다. IF는 **단일 자원 게이지**로 통합한다. 이름과 시각 디자인은 후에 결정해도 된다.

**보스 페이즈 + 시네마틱 처단 — 🟡 1~2개만**
모든 보스에 페이즈와 처단 모션을 만들면 아티스트 0인 우리 팀에선 데드락이다. **메인 보스 1~2명에만 처단 시퀀스**를 만들고, 나머지는 일반 KO 모션을 재사용한다. 페이즈 분기도 메인 보스 한정.

**실시간 절단 (ProceduralMesh) — ❌ Skip**
시각적 임팩트 대비 구현/디버깅 비용이 최악이다. 본 숨김 + 분리 매시 1~2개로 "절단처럼 보이게" 처리하면 충분하다.

**Showmaker 자체 연출 툴 — ❌ Skip**
SB는 Seq_ 64,877개를 자체 툴로 관리한다. UE5 Sequencer + Niagara + Animation Layer Interface로 대체할 수 있다. 우리에게 툴 개발은 사치다.

---

### 2.4 적 AI — 핵심만 차용 (Adapt)

SB는 117개 몬스터 BT + 페이즈 분기 보스로 다양성을 만든다. 우리는 두 가지만 가져간다.

**역할 분류 (Attacker / Defender / Ranged / Supporter) — ✅ Adopt**
적 종류를 적게 만들어도 **역할 조합으로 전투 상황의 다양성**을 만들 수 있다. IF는 **3역할(Attacker/Ranged/Supporter)** 부터 시작하는 게 적정하다.

**페이즈 전환 — 🟡 Adapt (보스 한정)**
StateTree(페이즈 분기) + BT(패턴 실행) 하이브리드 ([[13-UE5-GAS-설계안]] B-6 참조). 보스 1~2명에만 적용하고 일반 적은 단순 BT로 처리한다.

---

## 3. 정리: 우리가 SB에서 가져갈 핵심 3가지

문서 분량과 별개로 본질만 추리면 다음 셋이다.

1. **3스탯 인터록** — HP/Shield/Balance가 서로의 공략 도구가 되는 거울 구조.
2. **색상-대응 가위바위보** — 시각 신호로 학습 곡선을 직관화.
3. **방어가 공격을 해금하는 후속 상태 시스템** — 방어가 보상으로 직결되는 공수 전환.

나머지는 전부 **위 셋을 위한 보조 장치**이거나 **풀팀 사치품**이다. 우리 팀 규모에선 이 셋만 잘 구현해도 SB와 같은 결의 전투를 만들 수 있다.

## 4. SB가 안 한 것 = 우리 차별화 기회 (TODO)

이 섹션은 의도적으로 비워둔다. SB를 따라가기만 하면 "재미는 있지만 차별성은 없는 게임"으로 끝나기 쉽다. IF가 어떤 메커닉으로 SB와 다를지는 별도 브레인스토밍 세션에서 결정한다.

가능한 방향 (메모):

- 세계관/내러티브가 메커닉에 직접 영향을 주는 구조 — SB는 메커닉과 스토리가 분리되어 있음.
- 한 가지 큰 후크 (시간 조작, 위치 교환 등) — SB는 후크가 없는 정통 액션이라, 우리는 한 개 가져가면 차별점이 됨.
- 협동/2인 플레이 — SB는 완전한 솔로 액션.

→ `superpowers:brainstorming` 또는 `/oh-my-claudecode:deep-interview` 로 별도 진행 권장.

## 5. 검증 필요 / 미결정

- **판정 윈도우 12~13프레임** — 출처 불명. SB 디컴파일에서 실제 값 교차검증 필요.
- **DLC 추가 메커닉** — 본 문서에 미반영. DLC 클리어 직후 메모 따로 작성한 뒤 합칠 것.
- **시프트업 지원 시점의 포지셔닝** — SB와 너무 비슷하면 오히려 마이너스. "SB를 깊이 이해하되 명확한 차별점을 가진 팀"으로 보이는 것이 목표.
