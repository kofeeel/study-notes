# 낙원 Last Paradise — UE5 개발 학습 가이드

> 76,887개 에셋 분석 기반. 상용 UE5.6 게임의 아키텍처를 역분석하여 추출한 실전 설계 패턴 정리.

---

## 1. GAS (Gameplay Ability System) 설계 패턴

### 1-1. 핵심 원칙: "모든 액션은 GA"

낙원은 **195개 GA + 59개 GE + 9개 GC**로 게임플레이 전체를 GAS 위에 구축했다.
점프, 달리기, 문 열기, 보이스챗 토글까지 GA로 처리한다.

**왜 이렇게 하는가?**
- GA는 `Activation/Deactivation` 생명주기를 제공 → 상태 충돌 방지 (점프 중 공격 불가 등)
- GA에 `GameplayTag` 기반 조건을 걸 수 있음 → 복잡한 조건 분기를 코드 대신 태그로 처리
- 네트워크 리플리케이션이 내장되어 있음 → 멀티플레이어 동기화 자동 처리
- 쿨다운, 코스트(스태미나 등)를 GE로 분리 가능 → 밸런스 조정이 데이터 수정만으로 가능

**폴더 구조:**
```
AbilitySystem/Abilities/
├── Action/           → 캐릭터 기본 액션 (Jump, Sprint, Crouch, Emote...)
│   ├── Rigidify/     → CC 시스템 (Knockback, Stun, HitReaction)
│   ├── Skill/        → 액티브 스킬 (Kick, Rush, Rolling, Decoy, Trap...)
│   │   ├── BoxMode/
│   │   ├── Decoy/
│   │   ├── ListenMode/
│   │   ├── Rope/
│   │   ├── RopeDart/
│   │   └── Trap/     → BearTrap, Bait, TrapInstall
│   ├── Status/       → 상태이상 (Weary)
│   └── VoiceChat/    → 보이스챗 제어 (마이크/모드 토글)
├── Interact/          → 상호작용 (Door, Exit, Search, Collect, Housing)
├── Weapon/            → 무기 공격/방어 (Melee, Ranged, Throw)
├── UI/                → UI 전환 (MainMenu, Tablet, Radial)
└── Global/            → 라운드 시스템 (RoundStartReadyBlockAbilities)
```

**학습 포인트:**
- GA가 100개 넘어가면 **카테고리 폴더 분리**가 필수
- `Action/Rigidify/`처럼 CC(군중제어)를 독립 서브시스템으로 분리하면 유지보수가 쉬움
- `UI/` 폴더에 GA가 있는 것은 UI 열기/닫기도 어빌리티로 관리한다는 뜻 → 네트워크 동기화 용이

### 1-2. GameplayEffect 설계 패턴

59개 GE를 분석하면 명확한 네이밍/분류 규칙이 보인다.

**Duration 정책 접미사:**
| 접미사 | 의미 | 예시 |
|--------|------|------|
| `_Instant` | 즉시 적용 후 소멸 | `GE_Damage_Basic_Instant` |
| `_Infinite` | 영구 지속 (수동 제거) | `GE_Cooldown_Infinite`, `GE_DecreaseMoveStamina_Infinite` |
| `_Duration` | 지정 시간 후 소멸 | `GE_Duration_Heal_Basic_SetByCaller` |

**값 전달 방식:**
| 패턴 | 설명 | 예시 |
|------|------|------|
| `_SetByCaller` | 런타임에 수치 주입 | `GE_Damage_Basic_SetByCaller`, `GE_Weight_SetByCaller` |
| `_Basic` | 고정값 | `GE_Eat_Basic` |
| (없음) | 기본 동작 | `GE_Death`, `GE_Blind` |

**학습 포인트:**
- `SetByCaller` 패턴이 압도적으로 많음 → **하나의 GE를 재사용**하면서 수치만 바꾸는 것이 실전 표준
- `GE_Death`처럼 특수 이벤트도 GE로 처리 → `PostGameplayEffectExecute`에서 사망 로직 트리거
- 쿨다운도 GE로 분리: `GE_Cooldown_Sprint`, `GE_Cooldown_Kick` 등 스킬별 개별 쿨다운 GE

**어트리뷰트 목록 (GE에서 추론):**
```
Health, MaxHealth
MoveStamina, MaxMoveStamina
Mental
Infection, MaxInfection
BlackOut (기절), BlackOutLimit, BlackoutRecoverRate
InjuryRate
Food
Weight
SightAggroScale (AI 감지 스케일)
```

→ 서바이벌 장르에 필요한 **다층 스탯 시스템** 설계 참고 자료로 매우 유용

### 1-3. 듀얼 윌드 무기 조합

26가지 좌/우 무기 조합을 개별 GA로 관리:
```
GA_MeleeAttack_RAxeLAxe      GA_MeleeAttack_RAxeLDagger
GA_MeleeAttack_RAxeLHammer    GA_MeleeAttack_RAxeLKnife
GA_MeleeAttack_RAxeLStick     GA_MeleeAttack_RDaggerLAxe
...
```

**패턴:** `GA_MeleeAttack_R{우측무기}L{좌측무기}`

**학습 포인트:**
- 5종 무기(Axe, Dagger, Hammer, Knife, Stick) × 5 = 25 조합 + BareHand
- 각 조합이 별도 GA → 조합별 고유 애니메이션/데미지/타이밍 가능
- 조합 폭발 문제를 GA 파일 분리로 해결 (코드 복잡도 대신 파일 수로 전환)

## 2. AI 시스템 (좀비 AI)

### 2-1. 계층적 BehaviorTree 아키텍처

```
BT_ZombieBase (루트)
├── BT_IdleState
│   ├── BT_Idle
│   ├── BT_IdleWithoutPath
│   ├── BT_JustRoaming
│   └── BT_RoamingWithPath
├── BT_SuspiciousState
│   ├── BT_LookAround
│   └── BT_MoveToSearchPos
├── BT_InvestigateState
│   └── BT_Search
└── BT_AggressiveState
    ├── BT_AggressiveCore (기본)
    ├── BT_AggressiveCore_Armored
    ├── BT_AggressiveCore_Butcher
    ├── BT_AggressiveCore_Gatherer
    ├── BT_AggressiveCore_Policeman
    └── BT_AggressvieCore_Runner
```

**학습 포인트:**
- **3단 분리**: Base → State → Behavior로 책임을 나눔
- **상태머신을 BT 서브트리로 구현**: `BT_IdleState` 등이 각 상태의 진입점
- **4단계 경계심**: Idle → Suspicious → Investigate → Aggressive
- **타입별 오버라이드**: 기본 `BT_AggressiveCore`를 공유하되, Armored/Butcher 등은 전용 서브트리

### 2-2. 좀비 타입별 특성

| 타입 | 에셋 수 | 공격 패턴 | 특징 |
|------|------:|---------|------|
| Ordinary | 18 | 기본 근접 | 가장 흔한 좀비, 장비 변형 있음 |
| Armored | 101 | Charged Attack, Stationary | 방어력 높음, 충전 공격 |
| Butcher | 101 | Combo Attack, Mobile/Stationary | 콤보 공격 |
| Gatherer | 109 | Combo, Top Attack | 상단 공격 패턴 |
| Policeman | 199 | BiteNeck, Combo | 가장 복잡한 AI, 물기 공격 |
| Screamer | 38 | Howl, Scream | 소리로 다른 좀비 소환 |
| Runner | 44 | Run_Bite, 빠른 물기 | 고속 추적 |

**학습 포인트:**
- **Mobile vs Stationary Attack 분리**: 이동 중 공격 / 정지 후 공격이 별도 BT
- **EQS 스폰 시스템**: 5종 스폰 전략으로 지형에 맞는 좀비 배치
  - `EQS_ZombieSpawnSpot` — 기본
  - `EQS_ZombieSpawnSpot_100uu` — 좁은 공간
  - `EQS_ZombieSpawnSpot_Narrow` — 복도
  - `EQS_RangeSpawner_Cube` / `XYGrid` — 영역 기반
- **오브젝트 풀링**: `BT_ReturnToPool` + `BT_Resurrect` → 좀비 재사용으로 메모리 절약

```
DA_TabletApp_WorldMap      → 태블릿 월드맵 앱 설정
```

**학습 포인트:**
- `DA_AS_Active_*` (12개): 모든 액티브 스킬의 데이터를 DA로 관리
- `DA_Interaction_*` (30+개): 상호작용 행동을 DA로 정의
- `DA_EAS_*` (13개): GameMode별 컴포넌트/HUD/입력 조합을 DA로 설정
- `DA_PD_*` (6개): 플레이어 데이터 프리셋 (Default, AI, Entry, Lobby, Tutorial)

→ **새 스킬 추가 = DA 파일 하나 생성** 수준의 확장성

## 5. 네트워크 & 게임 모드

### 5-1. GameMode 분리 전략

```
BP_EntryGameMode              → 게임 진입점 (로그인/타이틀)
BP_LobbyGameMode              → 로비 (캐릭터 선택/매칭)

```

**학습 포인트:**
- **로컬 vs 온라인 GameMode 분리**: `BP_InGameMode`(로컬) vs `BP_OnlineInGameMode`(멀티)
- 7개 GameMode → 게임 흐름의 각 단계를 명확히 분리
- 각 GameMode에 대응하는 DA: `DA_EAS_InGameComponents`, `DA_EAS_LobbyDefaultComponents` 등

### 5-2. GameState & PlayerState

```
GameState:
├── BP_InGameState             → 인게임 상태 (라운드, 시간 등)
├── BP_OutGameState            → 아웃게임 상태
└── BP_WeatherGameStateComponent → 날씨 (컴포넌트로 분리)

PlayerState:
├── B_PSPlayerState            → 플레이어 상태
└── BP_VoiceChatPlayerStateComponent → 보이스챗 (컴포넌트로 분리)

Session:
├── BP_DefaultSessionComponent
├── BP_ShootingPracticeSessionComponent
└── BP_TutorialSessionComponent
```

**학습 포인트:**
- **날씨가 GameState 컴포넌트** → 모든 클라이언트에 자동 리플리케이션
- **보이스챗이 PlayerState 컴포넌트** → 플레이어별 보이스 상태 동기화
- **Session 컴포넌트 분리** → 모드별 세션 로직 독립

## 6. 서바이벌 고유 시스템

### 6-1. 다층 스탯 시스템

```
체력 계열:    Health / MaxHealth / Heal
스태미나:     MoveStamina / MaxMoveStamina
정신력:       Mental
감염:         Infection / MaxInfection
부상:         InjuryRate / BlackOut / BlackOutLimit / BlackoutRecoverRate
음식:         Food
무게:         Weight
AI 감지:      SightAggroScale (BoxMode 등으로 변동)
```

→ 6개 독립 자원 + 상호작용 → 서바이벌 게임 스탯 설계의 좋은 참고

### 6-2. 탈출 시스템

```
PublicExit       → 공개 탈출구 (모든 플레이어 위치 표시)
SecretExit       → 비밀 탈출구
ManholeExit      → 맨홀 탈출
MiddleExit       → 중간 탈출
EmergencyExit    → 긴급 탈출
TimerExit        → 시간제 탈출
```
