# 19. 전투 · 타격감 · 조작 구현 가이드 (SB → UE5.7+GAS 매핑)

> SB 분석 + 언리얼 페스트 2024 발표를 IF 액션게임 옆에 두고 보는 **구현 참조**.
> 아키텍처 큰 그림: [[13-UE5-GAS-설계안]] / AI BT 노드: [[17-프로그래머-레퍼런스]] / BT 패턴: [[18-디자이너-레퍼런스]]

## 목표
- 전투 1사이클(입력→판정→타격감→반응)을 **5개 시스템 조합**으로 분해해 IF에서 구현 가능하게 매핑
- SB의 UE4 우회 기술은 UE5.7 네이티브로 치환, 손맛 핵심 3층은 그대로 이식
- 코드/태그/에셋 위치까지 단계별 명시 — 시작점 모호함 제거

## 1. 학습 우선순위 (80/20)

전투 손맛의 80%는 아래 5개에서 결정. 위에서부터 구현.

| # | 시스템 | SB 근거 | UE5 구현 핵심 | 난이도 |
|---|--------|---------|--------------|--------|
| ★★★ | **타격감 3층** | 페스트 2024 §3.2 | GameplayCue 1개 + AnimNode 2개 + WPO 머티리얼 | 중 |
| ★★★ | **이중 타격 판정** | 페스트 2024 §1.2 | `AT_WeaponTrace` (소켓 보간 + Sweep) | 중 |
| ★★★ | **콤보 윈도우** | Sound/Skill 5,048 + ChainStab | `AT_WaitComboInput` + Montage Section | 하 |
| ★★ | **MoveCurve** | `MoveCurve/` 131 에셋 | Motion Warping + 커스텀 AT | 중 |
| ★★ | **패링/회피 i-frame** | Sound/Skill: Parry/PerfectDodge | GE Duration + GameplayTag(Invincible) | 하 |

→ 이 5개만 정확히 만들면 SB가 PS5에서 보여준 손맛의 80%는 재현 가능.

## 2. 입력 → 콤보 윈도우

### 입력 매핑 (Enhanced Input)

| Action | IA | Trigger | 결과 GA |
|--------|-----|---------|--------|
| 약공격 | `IA_LightAttack` | Pressed | `GA_LightAttack` |
| 강공격 | `IA_HeavyAttack` | Pressed/Hold(차지) | `GA_HeavyAttack` |
| 회피 | `IA_Dodge` | Pressed (Tap) | `GA_Dodge` |
| 회피(퍼펙트) | `IA_Dodge` | 피격 윈도우 내 Pressed | `GA_PerfectDodge` |
| 패링 | `IA_Parry` | Pressed | `GA_Parry` |
| 베타스킬 1~4 | `IA_BetaSkill_N` | Pressed | `GA_BetaSkill_SlotN` |
| 락온 토글 | `IA_LockOn` | Pressed | LockOn Subsystem 호출 |

### 콤보 윈도우 (입력 버퍼링)

```cpp
// GA_LightAttack ActivateAbility
void UGA_LightAttack::ActivateAbility(...)
{
    PlayMontageAndWait(ComboMontage, ComboSection_N);

    // 콤보 윈도우 동안 입력 대기
    UAT_WaitComboInput* Task = UAT_WaitComboInput::WaitComboInput(
        this, ComboInputTag, /*WindowStart*/ 0.4f, /*WindowEnd*/ 0.85f);
    Task->OnInputReceived.AddDynamic(this, &ThisClass::OnComboInput);
    Task->OnWindowEnded.AddDynamic(this, &ThisClass::OnComboFailed);
    Task->ReadyForActivation();
}

void UGA_LightAttack::OnComboInput()
{
    // 다음 섹션으로 점프 → 새 GA 호출 안 하고 같은 GA 안에서 체이닝
    MontageJumpToSection(GetNextComboSection());
}
```

**핵심**: 윈도우 시작/종료 시간을 `UComboDefinition` DataAsset에서 읽음 → 디자이너가 코드 수정 없이 손맛 튜닝.

## 3. 공격 1사이클 — 라이프사이클 (외울 것)

```
[Input] IA_LightAttack
  → ASC->TryActivateAbilityByTag(Ability.Combo.Light.1)
  → GA_LightAttack 활성 + Tag(State.Combat.Attacking) 부여
    → Montage 재생 (Notify: AT_WeaponTrace 시작/종료)
    → AT_WeaponTrace: 소켓(SwordTip_Start ↔ SwordTip_End) 매 프레임 캐싱 + 보간
      → Hit 발생 → FGameplayAbilityTargetData_SingleTargetHit
        → ApplyGE(GE_Damage_Physical, SetByCaller=AttackPower)
        → ApplyGE(GE_HitImpact, Instant) → Tag(GameplayCue.Combat.HitImpact.Light)
          → GC_HitImpact 실행 (3층 동시 발화)
            ├ HitStop:    Attacker.Montage_Pause(0.08s) + Victim.Montage_Pause(0.12s)
            ├ BoneShake:  Victim AnimBP의 BoneShakeNode에 Impulse Push
            └ VertexShake: Victim 머티리얼 MPC: HitPos + HitTime 갱신
        → Victim.GA_HitReaction 활성 (Stagger or KnockBack)
      → Combo 윈도우 입력 ↔ 다음 Section
    → Montage 종료 → Tag(State.Combat.Attacking) 제거
```

**이 흐름이 모든 공격의 척추**. 강공격/스킬도 GA만 다를 뿐 동일.

## 4. 이중 타격 판정 — Triangle vs Sweep

### 판정 방식 선택

| 무기 종류 | 방식 | UE5 구현 |
|----------|------|---------|
| 검·창 (얇음) | **Triangle**: 이전/현재 소켓 2점 + 캐릭터 root = 삼각형 | `Triangle vs Capsule` 직접 검사 (3D Plane 교차) |
| 둔기·박치기 (덩어리) | **Sweep**: ShapeComponent + 이전 트랜스폼 | `World->SweepMultiByChannel(BoxShape, Prev → Curr)` |

### `AT_WeaponTrace` 핵심

```cpp
// 매 Tick: 소켓 위치 캐싱 + 이전 프레임과 보간
void UAT_WeaponTrace::TickTask(float DeltaTime)
{
    FVector CurStart = Mesh->GetSocketLocation("Weapon_Start");
    FVector CurEnd   = Mesh->GetSocketLocation("Weapon_End");

    // ★ 보간 핵심: 빠른 공격/저프레임 시 궤적 누락 방지
    const int32 SubSteps = FMath::Clamp(
        FMath::CeilToInt(FVector::Dist(PrevEnd, CurEnd) / TraceStepDistance), 1, 8);

    for (int32 i = 1; i <= SubSteps; ++i)
    {
        float T = (float)i / SubSteps;
        FVector StepStart = FMath::Lerp(PrevStart, CurStart, T);
        FVector StepEnd   = FMath::Lerp(PrevEnd,   CurEnd,   T);

        if (TraceMode == ETraceMode::Triangle)
            DoTriangleHitCheck(PrevEnd, StepEnd, CurStart);  // 삼각형 vs 적 캡슐
        else
            DoSweepCheck(StepStart, StepEnd);                 // Sweep
    }
    PrevStart = CurStart; PrevEnd = CurEnd;
}
```

**경사지 보정**: `AnimBP`에 Look-at IK 노드 — `Tag(State.Combat.Targeting)` 활성 시 상체가 타겟 중점을 바라봄 → SB의 Look-at IK 그대로 재현. UE5에선 **Motion Warping**으로 회전 + 위치 동시 보정도 가능.

## 5. 타격감 3층 — Hit Stop / Bone Shake / Vertex Shake (★ 손맛의 심장)

3층이 **동시에** 발화해야 손맛이 완성. 하나라도 빠지면 임팩트가 죽음.

| 층 | 시간 | 강도 (Light/Heavy/Crit) | 구현 |
|---|------|----------------------|------|
| **Hit Stop** | 0.05~0.15s | 0.06s / 0.10s / 0.18s | Attacker+Victim Montage `SetPlayRate(0)` |
| **Bone Shake** | 0.15~0.30s | 진폭 1cm / 3cm / 6cm | AnimBP 커스텀 AnimNode (Spine/Hip 본 perturbation) |
| **Vertex Shake** | 0.10~0.25s | WPO 0.5cm / 1.5cm / 3cm | 머티리얼 WPO + MPC |

### 5-1. Hit Stop

```cpp
// GC_HitImpact::HandleGameplayCue (OnExecute)
void UGC_HitImpact::OnExecute_Implementation(AActor* Target, const FGameplayCueParameters& P)
{
    const float Strength = P.RawMagnitude;  // 0.06 / 0.10 / 0.18
    PauseMontage(GetAttacker(P), Strength * 0.7f);  // 공격자는 짧게
    PauseMontage(Target,        Strength);          // 피격자는 길게

    // ★ IK 밀착감 보정: 멈춘 동안 검끝이 적 표면에 접촉 유지
    if (UWeaponIKComponent* IK = GetAttacker(P)->FindComponentByClass<UWeaponIKComponent>())
        IK->SnapWeaponToHitPoint(P.Location, Strength);
}
```

> **왜 IK 보정이 필요한가**: HitStop만 걸면 검이 적을 관통하거나 못 닿은 상태로 멈춤 → 어색함.
> SB는 "검 끝이 살짝 박혀 멈춘 느낌"을 IK로 강제.

### 5-2. Bone Shake (커스텀 AnimNode)

```cpp
// FAnimNode_BoneShake : public FAnimNode_SkeletalControlBase
void FAnimNode_BoneShake::EvaluateSkeletalControl_AnyThread(
    FComponentSpacePoseContext& Output, TArray<FBoneTransform>& OutBoneTransforms)
{
    const float T = TimeSinceImpact / Duration;
    if (T >= 1.f) return;

    // 감쇠 사인 — 처음 강하게, 빠르게 가라앉음
    float Atten = FMath::Pow(1.f - T, 2.f);
    FVector Wobble = ImpulseDir * (FMath::Sin(T * PI * Frequency) * Atten * Amplitude);

    for (const FBoneReference& Bone : ShakeBones)  // Spine_01, Spine_02, Pelvis 권장
    {
        FCompactPoseBoneIndex Idx = Bone.GetCompactPoseIndex(BoneContainer);
        FTransform Local = Output.Pose.GetLocalSpaceTransform(Idx);
        Local.AddToTranslation(Wobble);
        OutBoneTransforms.Add({Idx, Local});
    }
}
```

`OnGameplayCueExecute` 시 `ImpulseDir = HitNormal`, `TimeSinceImpact = 0` 리셋.

### 5-3. Vertex Shake (머티리얼 WPO)

```hlsl
// Material WPO (간략 의사코드)
float3 ToHit = WorldPosition - MPC_HitPos;
float  Dist  = length(ToHit);
float  TimeT = saturate((Time - MPC_HitTime) / Duration);   // 0→1
float  Falloff = saturate(1 - Dist / Radius);                // 거리 감쇠
float  Wave  = sin(TimeT * PI) * (1 - TimeT);                // 시간 감쇠
return -normalize(ToHit) * Wave * Falloff * Amplitude;        // 안쪽으로 눌림
```

**MPC (MaterialParameterCollection)**:
- `MPC_HitFeedback.HitPos` (Vector3) / `HitTime` (float) / `HitStrength` (float)
- `GC_HitImpact`에서 `SetVectorParameterValue` / `SetScalarParameterValue` 호출

→ 적 메시 표면이 **타격 부위 안쪽으로 살짝 눌렸다 복원**. SB의 "고기 맞는 느낌"의 핵심.

## 6. MoveCurve → Motion Warping (UE5 치환)

SB는 `MoveCurve` 131개로 공격/넉백 궤적을 제어. UE5.7에선 **Motion Warping이 90% 대체** + 잔여는 커스텀 AT.

| SB 패턴 | UE5 매핑 |
|---------|---------|
| `M_Behemoth_JumpAttackHigh_*` (도약 거리/높이 커브) | Motion Warping `Sync Point` (타겟 위치) + Animation Curve |
| `KnockDown_Forward_Eve_Move1_Curve` (피격 후 미끄러짐) | `AT_ApplyMoveCurve` (`UCurveFloat` → `LaunchCharacter` 매 틱) |
| `M_Common_KnockBack_Curve` (공통 넉백) | `GE_KnockBack` (Instant) + SetByCaller(Distance) → Cue가 커브로 LaunchCharacter |
| 락온 시 적 방향 자동 보정 | Motion Warping `RotationWarp` |

```cpp
// AT_ApplyMoveCurve 핵심
void UAT_ApplyMoveCurve::TickTask(float DT)
{
    Elapsed += DT;
    float Alpha = Elapsed / Duration;
    if (Alpha >= 1.f) { EndTask(); return; }

    float Forward = ForwardCurve->GetFloatValue(Alpha);  // SB MoveCurve 그대로 import 가능
    float Up      = ZCurve->GetFloatValue(Alpha);

    FVector Delta = Owner->GetActorForwardVector() * (Forward - PrevForward)
                  + FVector::UpVector * (Up - PrevUp);
    Owner->AddActorWorldOffset(Delta, /*sweep*/ true);
    PrevForward = Forward; PrevUp = Up;
}
```

> SB의 `.uasset` MoveCurve를 추출하면 그대로 `UCurveFloat`로 import 가능 — 손맛 수치 그대로 재사용.

## 7. 패링 / 회피 — i-frame과 보상 윈도우

| 액션 | i-frame | 보상 |
|------|--------|------|
| `GA_Dodge` | 0.20s (`GE_DodgeInvincible` Duration) | 없음 (생존만) |
| `GA_PerfectDodge` | 피격 직전 0.15s 윈도우 내 회피 입력 | `GE_PerfectDodgeReward` 1.5s: 시간 슬로우 0.4× + 카운터 윈도우 |
| `GA_Parry` | 0.12s 윈도우 | 적 `GE_ParryStun` 2s + 카메라 줌인 + `GC_ParrySuccess` |

```cpp
// 피격 시 PerfectDodge 판정
void UGA_HitReaction::ActivateAbility(...)
{
    // 0.15s 동안 회피 입력 대기
    UAT_WaitGameplayEvent::WaitGameplayEvent(this, Tag_Event_DodgeInput, /*timeout*/ 0.15f)
        ->EventReceived.AddDynamic(this, &ThisClass::OnPerfectDodgeTriggered);
}

void UGA_HitReaction::OnPerfectDodgeTriggered(FGameplayEventData Data)
{
    // 데미지 GE 취소 + Reward GE 부여 + 시간 슬로우
    CancelAbilitiesByTag(Tag_Cancel_OnPerfectDodge);
    ApplyGameplayEffect(GE_PerfectDodgeReward);
    UGameplayStatics::SetGlobalTimeDilation(GetWorld(), 0.4f);
    // 1.5초 후 복귀 (별도 타이머)
}
```

**튜닝 포인트**: 윈도우 0.15s가 너무 빡세면 좌절, 너무 넓으면 무성의. SB 기준 **8~12프레임(60fps)** 가 표준.

## 8. 햅틱 / 사운드 (비주얼 외 손맛 레이어)

비주얼 3층만으론 부족. SB는 **사운드 + DualSense 햅틱**까지 4층 레이어.

| 레이어 | SB 에셋 수 | UE5 구현 |
|-------|----------|---------|
| 사운드 (Wwise) | Sound/Skill 5,048 / Haptic 5,898 | Wwise 통합. 무료면 MetaSounds + Steam Input Haptics |
| 햅틱 | DualSense 5,898 데이터 | `UInputDeviceProperty` (UE5.3+) — 충격마다 트리거 저항+진동 |
| 카메라 | — | `GC_HitImpact`에서 `CameraShake` (`UMatineeCameraShake`) + 미세 줌(FOV +1°) |
| 슬로우 | — | Critical Hit 시 `SetGlobalTimeDilation(0.5f, 0.1s)` |

**4층 동기화**: 모두 `GC_HitImpact_Light/Heavy/Critical` 단일 Cue에서 트리거 → 비주얼/사운드/햅틱/카메라가 항상 같은 프레임에 발화.

## 9. 손맛 체크리스트 (구현 시 옆에 두고 점검)

빌드해서 한 대 후려쳤을 때 모두 ✓ 나와야 손맛 OK.

- [ ] 검이 적 표면에서 **딱** 멈춤 (HitStop + IK 밀착)
- [ ] 적 몸통이 한 번 **출렁** (BoneShake)
- [ ] 맞은 부위가 **안쪽으로 눌렸다 복원** (VertexShake)
- [ ] 카메라가 **살짝 흔들림** (작게! 멀미 유발 금지)
- [ ] 사운드가 **타격 프레임과 정확히 일치** (1프레임 이상 어긋나면 즉시 어색)
- [ ] 패드 트리거가 **저항 변화** (DualSense / Steam Input)
- [ ] 콤보 마지막 타가 **앞 타들과 다른 무게감** (HitStop 0.18s, 슬로우 0.1s)
- [ ] Critical 히트 시 **다른 사운드 + 다른 VFX + 다른 햅틱**
- [ ] 적 사망 타에 **약간의 슬로우** (0.4× × 0.3s)
- [ ] 락온 중 공격이 **자동으로 적을 향함** (Motion Warping RotationWarp)

## 10. 추천 구현 순서

| 주차 | 구현 | 검증 |
|------|------|------|
| W1 | Enhanced Input + GA_LightAttack 1단 + Montage | 입력→몽타주 재생 |
| W2 | AT_WeaponTrace (Sweep) + GE_Damage | 피격 시 HP 감소 |
| W3 | **GC_HitImpact 3층** (HitStop + BoneShake + VertexShake) | 손맛 1차 — ★마일스톤 |
| W4 | 콤보 윈도우 + AT_WaitComboInput + 3타 체인 | 콤보 흐름 |
| W5 | GA_Dodge + GA_PerfectDodge (i-frame + 슬로우) | 회피 손맛 |
| W6 | GA_Parry + ParryStun + Cue | 패링 손맛 |
| W7 | MoveCurve → Motion Warping + 넉백 | 피격 반응 |
