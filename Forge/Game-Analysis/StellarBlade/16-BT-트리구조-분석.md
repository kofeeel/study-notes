## 2. 공통 BT 스켈레톤 (전 몬스터 공유)

149개 BT를 분석한 결과, **거의 모든 몬스터가 동일한 루트 구조**를 공유:

```
Root Selector
 └── Selector [IsAlive(Self)]              ← 자기 생존 확인
     ├── DetectTarget [DetectResult(==)]    ← 타겟 탐지
     ├── Selector [IsAlive(Target)]         ← 타겟 사망 시 대기
     │   └── Wait(1.0s)
     └── Selector [IsAlive(Target)]         ← 타겟 생존 → 전투 진입
         ├── Wait(2.0s) [CheckActorEffect(Target.Item_Resurrection_Ground)]
         │                                  ← 부활 아이템 사용 중 대기
         ├── Selector [CheckActorEffect(Target.다운상태)]
         │   └── CautionToTarget [TimeLimit]  ← 다운된 적 경계
         └── Selector [AggroLevel(Peaceful)]  ← 비전투 상태 필터
             └── ★ 여기부터 몬스터별 고유 전투 로직 ★
```

**핵심 관찰:**
- **IsAlive → DetectTarget → IsAlive(Target)** 3단계 검증이 표준
- `Item_Resurrection_Ground` 이펙트 체크: 플레이어 부활 중 2초 대기 (공정성)
- `AggroLevel_Peaceful` 필터: 비전투 시 전투 로직 진입 차단
- 이 스켈레톤은 NPC AI에서도 거의 동일하게 사용됨

## 3. 보스 AI 설계 패턴 (실데이터)

### 3.1 HP 기반 페이즈 전환

모든 보스가 `CheckActorStat(HP)` + `CheckStance`로 페이즈 분기:

| 보스 | 페이즈 분기 | 스탠스 |
|------|-----------|--------|
| **Raven** | HP>60% / HP<=60% | `M_Raven_Default` → `M_Raven_Phase2` |
| **ExoSuit** | HP>70% / HP<=70% / HP<=30% | `M_ExoSuit_Default` → `PhaseChange` |
| **ElderPhase2** | HP>60% / HP<=60% / HP<=40% | + `M_ElderPhase2_Phase2` 이펙트 |
| **Behemoth** | HP 구간별 | 스탠스 + 이펙트 조합 |

**패턴**: `CheckActorStat(HP<=X%) && CheckStance(CurrentStance)` → Selector로 해당 페이즈 행동 선택

```
├── Selector [HP>60% && Stance=Default]     ← Phase 1 행동들
│   ├── ...
│   └── ...
└── Selector [HP<=60% && Stance=Phase2]     ← Phase 2 행동들
    ├── ...
    └── ...
```

**UE5 재현 시**: `CheckActorStat` → GAS `GameplayAttribute` 체크, `CheckStance` → `GameplayTag` 체크

### 3.2 패리/카운터 체인 시스템

Raven AI에서 발견된 복합 패리 시스템:

```
UseSkill(ParryPreview1)                     ← 패리 예고 동작
 ↓ [ParryPreviewChain1 이펙트 활성화]
UseSkill(Parry)                             ← 실제 패리
 ↓ [ParryChain 이펙트 활성화]
 ├── [GrabCheck OFF] → BetaGrabChain → BetaCounterGrab
 ├── [GrabCheck ON]  → BetaGrab
 └── BetaRapidCombo | BetaChargeCombo       ← 대안 콤보
 ↓
UseSkill(ParryPreview2)                     ← 2차 패리 예고
 ↓ [ParryPreviewChain2 활성화]
UseSkill(ParryCounterCombo)                 ← 카운터 콤보
```

**핵심**: `CheckActorEffect` 이펙트 플래그로 콤보 상태를 추적. 블랙보드가 아닌 **이펙트 시스템**이 BT 상태 머신 역할.

### 3.3 플레이어 행동 반응 시스템

| 데코레이터 | 반응 | 빈도 |
|-----------|------|------|
| `AimMe` | 플레이어 조준 시 회피 | 121회 |
| `CheckActorEffect(HitProjectileResult)` | 원거리 피격 시 회피 | 다수 |
| `DistanceToTarget(dist>=X)` | 원거리 시 돌진/사격 | 956회 |
| `DistanceToTarget(dist<=X)` | 근거리 시 근접 콤보 | 다수 |
| `IsGroupTarget` | 그룹 타겟일 때만 | 102회 |
| `LastSkillHitResult` | 직전 스킬 적중 여부 | 25회 |

**ExoSuit 예시** (거리 기반 스킬 선택):
```
피격 시(HitProjectileResult):
  ├── dist > 400 → EvadeLeft|EvadeRight (30~50% 확률)
  ├── dist > 400 → BladeChaseCombo|ChaseCombo (접근 공격)
  ├── dist > 800 → EnergyBombShot|LaserCrossFire (원거리 대응)
  └── fallback → BackStepRushCounter
```

### 3.4 확률 기반 행동 다양성

`SBBTDecorator_SbRandom`으로 같은 상황에서도 다른 행동:

```
# BotAttacker 스폰 시 첫 행동
├── UseSkill(Missile) [Random(rand(100)<=40)]     ← 40%
├── UseSkill(Stamp)   [Random(rand(100)<=30)]     ← 30%  
└── UseSkill(Dash)    [Random(rand(100)<=30)]     ← 30%
```

**관찰**: 확률 합이 100%를 초과하는 경우도 있음 → Selector 순서 우선, 먼저 통과한 것 실행

### 4.1 역할별 BT 복잡도

| 역할 | 대표 | 평균 노드 | 특징 |
|------|------|---------|------|

| 잡몹 | MiteA (50) | 30~60 | 단순 접근→공격 |

### 4.2 MetaAI 연동 (그룹 전투)

```
Sequence [AggroLevel(Battle) && CheckActorEffect(Self.LV_MetaAction)]
 └── MetaAI                    ← 메타AI가 이 몬스터에게 행동 명령
```

- `LV_MetaAction` 이펙트 = 메타AI가 이 몬스터에 행동 요청 중
- `IsGroupTarget` / `IsGroupAttacker` = 그룹 전투에서의 역할 분배
- **81회** MetaAI 태스크 사용 → 주로 Bot계열 + 일부 인간형

### 4.3 귀환 시스템

```
Sequence [AggroLevel(Battle) && IsActiveSkill(NOT)]
 ├── UseSkill(BattleEnd)       ← 전투 종료 연출
 └── Blackboard(BattleState)

Sequence [AggroLevel(Battle) && ...IsActiveSkill(NOT)]
 └── MoveToHome [DetectResult(==)]  ← 홈 위치로 귀환
```

## 6. 핵심 설계 인사이트

### 6.1 이펙트 = 상태 머신

스텔라블레이드 AI의 가장 큰 특징: **블랙보드가 아닌 이펙트(Effect)가 BT 상태를 제어**.

- `CheckActorEffect`가 **1,873회**로 최다 사용 데코레이터
- 블랙보드는 주로 일회성 플래그 (FirstShot, BB1, BattleState)
- 이펙트는 복합 상태 추적 (파리체인, 페이즈, 쿨다운)

```
전통적 UE4 방식:          스텔라블레이드 방식:
BB.Phase = 2              CheckActorEffect(Phase2Effect)
BB.CanParry = true        CheckActorEffect(ParryChain)
BB.IsEnraged = true       CheckActorEffect(EnrageEffect)
```

**UE5 GAS 대응**: Effect → `GameplayTag` 부여/제거. `HasMatchingGameplayTag`로 체크.

### 6.2 스킬 배열 = 행동 다양성

`UseSkill`의 `SkillName`이 **배열**:
```json
"SkillName": ["M_Raven_BetaEvadeLeft", "M_Raven_BetaEvadeRight"]
```
→ 런타임에 배열에서 랜덤/조건부 선택. 단일 노드로 여러 변형 행동 표현.

### 6.3 쿨다운 = UseableTime + UseableTimeReset 쌍

```
Selector [UseableTime]          ← 쿨다운이 돌았는지 확인
 └── UseSkill(ChaseGrab)       ← 스킬 사용

Sequence [페이즈 전환 시]
 ├── UseableTimeReset           ← 모든 쿨다운 리셋 (6~8개 연속)
 ├── UseableTimeReset
 ├── ...
 └── Blackboard(BB)
```

페이즈 전환 시 `UseableTimeReset` 6~8회 연속 호출 → 모든 스킬 쿨다운 초기화.

### 6.4 FlowAbortMode 활용

```
IsAlive(Self)  → abort=Both     ← 죽으면 즉시 모든 하위 중단
IsAlive(Target) → abort=Both    ← 타겟 죽으면 즉시 중단
TimeLimit      → abort=Self     ← 시간 초과 시 자기만 중단
```

## 7. UE4 → UE5 전환 가이드

| SB (UE4.26) | UE5 GAS 대응 | 비고 |
|-------------|-------------|------|
| `SBBTTask_SbUseSkill` | `BTTask_ActivateAbility` | GA로 스킬 구현, SkillName 배열 → GA Tags |
| `CheckActorEffect` | `BTDec_HasGameplayTag` | 이펙트 → GameplayTag로 전환 |
| `CheckActorStat(HP)` | `BTDec_CheckAttribute` | GAS AttributeSet에서 HP 조회 |
| `CheckStance` | `BTDec_HasGameplayTag` | Stance → `State.Stance.Phase2` 태그 |
| `UseableTime/Reset` | GAS Cooldown GE | `UAbilitySystemComponent::GetCooldownTimeRemaining` |
| `UseEffect` | `ApplyGameplayEffectToSelf` | GE로 태그 부여 |
| `AggroLevel` | `AIPerception` + GameplayTag | `State.Aggro.Peaceful` / `State.Aggro.Battle` |
| `MetaAI` | 커스텀 AIFormation | EQS + AIController 확장 |
| `AimMe` | 커스텀 데코레이터 | 카메라 Forward dot (AI-Player) |
| `IsGroupTarget/Attacker` | AIFormation 시스템 | [[13-UE5-GAS-설계안]] 참고 |

### UE5에서 달라지는 점

1. **StateTree 활용**: 페이즈 전환은 StateTree가 더 적합 (HP 조건 → State 전환)
2. **EQS 복귀**: SB의 55×55 셀 그리드 → UE5는 EQS가 충분히 성능 개선됨
3. **GAS 태그 기반 조건**: `CheckActorEffect` 1,873회 → 모두 `GameplayTag` 체크로 통합
4. **Smart Object**: `CautionToTarget` 경계 행동 → UE5 Smart Object로 자연스러운 상호작용
5. **Mass Entity**: 대규모 잡몹 → Mass Entity + 간소화된 BT
