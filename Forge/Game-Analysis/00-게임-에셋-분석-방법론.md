# UE5 게임 에셋 분석 방법론

> 팀 공유용 가이드. 낙원(Last Paradise) 분석 사례 기반으로 정리.
> 스텔라블레이드 등 다른 UE 게임에도 동일하게 적용 가능.

---

## 1. 사용 도구

### 1-1. CUE4Parse (핵심 도구)

| 항목 | 내용 |
|------|------|
| **용도** | UE4/UE5 게임의 .pak / .utoc / .ucas 파일에서 에셋 구조를 추출 |
| **GitHub** | https://github.com/FabianFG/CUE4Parse |
| **언어** | C# (.NET) |
| **라이선스** | MIT |
| **지원 포맷** | `.uasset`, `.umap`, `.ubulk`, `.uptnl`, `.ushaderbytecode` 등 |

**CUE4Parse가 하는 일:**
- 패키징된 게임 파일(.pak)을 열어서 내부 에셋 **경로/이름/타입** 목록 추출
- 에셋 데이터(머티리얼, 텍스처, 메시, 블루프린트 등)를 파싱하여 구조 확인
- 블루프린트 직렬화 데이터를 읽어 클래스/프로퍼티 분석 가능

### 1-2. CUE4Parse 기반 GUI 도구 (선택)

| 도구 | 설명 | 링크 |
|------|------|------|
| **FModel** | CUE4Parse 기반 GUI 뷰어. 에셋 브라우징/미리보기/추출에 최적 | https://fmodel.app |
| **UE Viewer (umodel)** | 오래된 도구이나 메시/텍스처 미리보기에 유용 | https://www.gildor.org/en/projects/umodel |

> **추천**: FModel로 시각적 탐색 → CUE4Parse 코드로 대량 자동 추출

### 1-3. 분석 보조 도구

| 도구 | 용도 |
|------|------|
| **Claude Code (AI)** | 추출된 에셋 목록을 분석·분류·패턴 추출·문서 자동 생성 |
| **PowerShell / Bash** | 파일 목록 정렬, 접두사 카운팅, 통계 산출 |
| **Obsidian** | 분석 결과를 구조화된 노트로 정리, 위키링크로 상호 참조 |

## 2. 분석 파이프라인

```
┌─────────────────────────────────────────────────────┐
│  Phase 1: 에셋 추출                                  │
│  .pak/.utoc 파일 → CUE4Parse/FModel → 전체 에셋 목록  │
└──────────────────────┬──────────────────────────────┘
                       ▼
┌─────────────────────────────────────────────────────┐
│  Phase 2: 1차 분류                                   │
│  전체 목록 → 확장자/접두사/폴더별 통계 산출             │
└──────────────────────┬──────────────────────────────┘
                       ▼
┌─────────────────────────────────────────────────────┐
│  Phase 3: 시스템 분석                                 │
│  GAS / AI / UI / 네트워크 등 시스템별 심층 분석          │
└──────────────────────┬──────────────────────────────┘
                       ▼
┌─────────────────────────────────────────────────────┐
│  Phase 4: 학습 가이드                                 │
│  실전 설계 패턴 정리 + 자체 프로젝트 적용 체크리스트      │
└─────────────────────────────────────────────────────┘
```

## 3. Phase별 상세 절차

### Phase 1: 에셋 추출

**Step 1 — 게임 파일 위치 확인**
```
# Steam 게임 기준
Steam/steamapps/common/{게임이름}/Content/Paks/
```

**Step 2 — FModel로 1차 탐색**
1. FModel 실행 → Directory에 Paks 폴더 지정
2. UE Version 설정 (UE4 / UE5 — 게임에 따라 다름)
3. AES 키 입력 (필요 시 — 암호화된 pak의 경우)
4. Packages 탭에서 전체 폴더 트리 확인
5. 필요 시 에셋 미리보기 (텍스처, 메시 등)

**Step 3 — 전체 에셋 목록 추출**
```
# FModel → 전체 파일 목록 내보내기
# 또는 CUE4Parse 코드로 프로그래밍 방식 추출

# 결과물: 전체-에셋-목록.txt (낙원의 경우 76,887줄)
```

> **AES 키**: 대부분의 상용 게임은 pak 파일이 암호화됨.
> AES 키는 게임 바이너리에서 추출하거나, 커뮤니티에서 공유된 것을 사용.
> 검색: `{게임이름} AES key` 또는 `{게임이름} encryption key`

### Phase 2: 1차 분류 (통계 산출)

전체 에셋 목록 텍스트를 AI(Claude)에 전달하여 자동 분류:

**2-1. 확장자별 통계**
```
.uasset    →  블루프린트, 머티리얼, 텍스처 등 모든 UE 에셋
.ubulk     →  벌크 데이터 (텍스처/메시 원본)
.umap      →  레벨/맵 파일
.uexp      →  에셋 추가 데이터
```

**2-2. 접두사별 카운팅**
```bash
# 파일명에서 접두사 추출 후 빈도수 정렬
# 예시 결과:
# T_  4282  → Texture
# BP_ 1449  → Blueprint
# MI_ 1352  → MaterialInstance
# SM_ 1288  → StaticMesh
# GA_  195  → GameplayAbility
# BT_   41  → BehaviorTree
```

**2-3. 폴더 구조 분석**
- 1단계 폴더 = 주요 모듈 (Environment, Item, UI, Animation 등)
- 2단계 폴더 = 서브시스템 (AbilitySystem, AI, Weapons 등)
- 파일 수 기반 모듈 비중 파악

### Phase 3: 시스템별 심층 분석

접두사와 폴더 경로를 기반으로 각 시스템을 독립 문서로 분석:

| 분석 대상 | 식별 기준 | 핵심 파악 포인트 |
|-----------|----------|----------------|
| **프로젝트 구조** | 최상위 폴더 트리 | 모듈 분리 방식, 에셋 비중 |
| **GAS 전투** | `GA_`, `GE_`, `GC_` 접두사 | 어빌리티 카테고리, 이펙트 패턴, 네이밍 규칙 |
| **AI 시스템** | `BT_`, `BB_`, `EQS_`, `BTTask_`, `BTDecorator_` | BT 계층, 상태머신, 적 타입별 분화 |
| **캐릭터** | `Characters/`, `SK_`, `ABP_` | 스켈레탈 구조, 애님BP, 스킨 시스템 |
| **무기/아이템** | `Item/`, `Weapon/`, `DA_` | 아이템 분류, 데이터 드리븐 설계 |
| **UI** | `WBP_`, `UI/` | 위젯 카테고리, 공용 컴포넌트, UI 흐름 |
| **네트워크** | `GameMode`, `GameState`, `PlayerState` | 모드 분리, 리플리케이션 전략 |
| **월드/레벨** | `.umap`, `Maps/` | World Partition, 맵 구성, 스트리밍 |
| **오디오/VFX** | `Sound/`, `FX/`, `Wwise` | 오디오 미들웨어, 이펙트 구성 |
| **데이터 구조** | `DA_`, `DT_` | DataAsset/DataTable 설계 패턴 |
| **플러그인** | `Plugins/` | 사용 미들웨어, 마켓플레이스 에셋 |

### Phase 4: 학습 가이드 작성

분석 결과를 **자체 프로젝트에 적용 가능한 형태**로 종합:
- 각 시스템의 설계 패턴 요약
- "왜 이렇게 했는가" 추론
- 실전 적용 체크리스트

## 4. 결과물 구조 (Obsidian 노트)

```
FORGE/Game-Analysis/{게임이름}/
├── 00-INDEX.md              ← 목차 + 메타 정보 (총 파일 수, 분석 일시)
├── 01-프로젝트-구조.md       ← 폴더 구조, 모듈 분리, 플러그인
├── 02-에셋-통계.md           ← 확장자/접두사 분포
├── 03-GAS-전투시스템.md      ← GA/GE/GC 전수 목록 + 패턴
├── 04-AI-시스템.md           ← BT/EQS/Blackboard 분석
├── 05-캐릭터-시스템.md       ← 캐릭터/NPC/애니메이션
├── 06-무기-아이템.md         ← 무기, 소모품, 장비, 인벤토리
├── 07-UI-시스템.md           ← 위젯 목록 + 카테고리
├── 08-네트워크-게임모드.md    ← GameMode/GameState/PlayerState
├── 09-월드-레벨.md           ← 맵, 레벨 스트리밍
├── 10-오디오-VFX.md          ← 오디오 미들웨어, 이펙트
├── 11-데이터-구조.md         ← DataAsset/DataTable
├── 12-학습-가이드.md         ← 설계 패턴 종합 + 적용 체크리스트
└── 전체-에셋-목록.txt        ← CUE4Parse 추출 원본 (참조용)
```

## 5. 스텔라블레이드 분석 시 주의사항

| 항목 | 낙원 | 스텔라블레이드 (예상) |
|------|------|-------------------|
| **엔진** | UE5.6 | UE4 (PS5 독점 → PC 포트) |
| **장르** | 서바이벌 PvPvE | 액션 RPG (싱글) |
| **GAS 사용** | 확인됨 (195 GA) | 확인 필요 |
| **AI 시스템** | BT 기반 좀비 AI | 보스/일반몬스터 AI 패턴 예상 |
| **네트워크** | 멀티플레이어 | 싱글플레이어 (리플리케이션 없을 수 있음) |
| **pak 암호화** | AES 키 필요 | AES 키 필요 (검색 필요) |
| **핵심 분석 포인트** | GAS + AI + 서바이벌 스탯 | 전투 시스템 + 보스 AI + 스킬 트리 |

**스텔라블레이드 분석 시 추가로 볼 것:**
- 콤보 시스템 / 파링 / 회피 메커니즘 (액션 게임 특화)
- 보스 AI 패턴 (페이즈 전환, 패턴 분기)
- 스킬 트리 / 성장 시스템 구조
- 장비 + 코스튬 시스템 (비주얼 변경)
- 컷씬 / 시네마틱 시스템
