#flashcards/OS

프로세스와 스레드의 차이는?
?
- 프로세스 = 독립 메모리(코드/데이터/힙/스택), IPC로 통신, 크래시 격리
- 스레드 = 코드/데이터/힙 공유 + 스택만 독립, 통신 빠름, 하나 죽으면 프로세스 전체 영향
<!--SR:!2026-05-27,1,230-->

컨텍스트 스위칭이란?
?
실행 중인 프로세스/스레드 상태(PC·레지스터·SP)를 PCB에 저장하고 다음 것을 복원.
순수 오버헤드 + TLB 플러시/캐시 미스 유발. 스레드 간이 프로세스 간보다 저렴.
<!--SR:!2026-05-27,1,230-->

데드락의 4가지 필요조건은?
?
상호배제 / 점유대기 / 비선점 / 순환대기. 하나만 깨도 데드락 없음.
대응: 예방(조건 차단) / 회피(Banker's) / 탐지+회복.
<!--SR:!2026-05-27,1,230-->

뮤텍스와 세마포어의 차이는?
?
- 뮤텍스: 소유권 있음(잠근 자가 해제), 0/1, 단일 자원 보호
- 세마포어: 소유권 없음, 0 이상 카운팅, N개 자원/시그널링
<!--SR:!2026-05-27,1,230-->

가상 메모리란?
?
물리 메모리 크기와 무관하게 프로세스마다 독립적 대형 주소공간 제공.
페이지 테이블로 VA→PA 변환, 실제 쓰는 페이지만 로드(Demand Paging). 보호·공유·스왑 가능.
<!--SR:!2026-05-27,1,230-->

페이지 폴트 처리 과정은?
?
1) 폴트 예외 발생 2) OS가 디스크(스왑)에서 페이지 탐색 3) 빈 프레임 선택(없으면 교체)
4) 메모리로 로드 5) 페이지 테이블 갱신 후 명령어 재실행. 과다 발생 = 스래싱.
<!--SR:!2026-05-27,1,230-->

캐시와 지역성의 원리는?
?
CPU-메모리 사이 고속 소형 메모리. 자주 쓰는 데이터 보관.
- 시간 지역성: 최근 접근 데이터 재접근
- 공간 지역성: 인접 주소 접근(캐시 라인 단위)
<!--SR:!2026-05-27,1,230-->

동기화가 필요한 이유는?
?
멀티스레드가 공유 자원 동시 접근 시 레이스 컨디션 발생(예: count++ 읽기-수정-쓰기 분리).
임계구역 상호배제로 일관성 보장. 메모리 가시성 위해 메모리 배리어도 필요.
<!--SR:!2026-05-27,1,230-->

스레드 풀(Thread Pool)이란?
?
미리 만든 스레드 집합에 작업 할당 후 반환. 생성/소멸 오버헤드 제거 + 자원 사용 제한.
최적 수: CPU-bound≈코어수, I/O-bound≈코어수×(1+대기/CPU).
<!--SR:!2026-05-27,1,230-->

LRU 페이지 교체 알고리즘은?
?
가장 오래 안 쓴 페이지 교체. 시간 지역성 기반, 이론 성능 우수하나 추적 오버헤드 큼.
실무는 Clock(NRU)으로 근사: 참조 비트 0인 페이지를 시계방향 순회로 선택.
<!--SR:!2026-05-27,1,230-->

선점형 vs 비선점형 스케줄링?
?
- 선점형: OS가 강제로 CPU 회수(타임슬라이스/우선순위). 응답성↑, 오버헤드↑. 현대 OS 표준
- 비선점형: 자발적 양보까지 실행. 단순하나 긴 작업이 독점
<!--SR:!2026-05-27,1,230-->

유저 스레드 vs 커널 스레드?
?
- 유저: 라이브러리 관리, 커널 모름. 빠르나 한 스레드 블로킹 시 전체 블록(M:1)
- 커널: OS 직접 관리, 진짜 병렬, 블로킹 격리(1:1). 현대 OS 기본
<!--SR:!2026-05-27,1,230-->

TLB(Translation Lookaside Buffer)란?
?
페이지 테이블 조회를 가속하는 CPU 내부 하드웨어 캐시(VA→PA 변환 쌍 저장).
TLB 히트 시 메모리 접근 없이 즉시 변환. 컨텍스트 스위치 시 플러시(ASID로 최소화).
<!--SR:!2026-05-27,1,230-->

스래싱(Thrashing)이란?
?
물리 메모리 부족으로 페이지 폴트 폭증, 교체에 시간 다 써서 실작업 정지.
원인: 다중프로그래밍 정도 과다. 해결: 워킹셋 모델, PFF 제어, 프로세스 수 감소/증설.
<!--SR:!2026-05-27,1,230-->

COW(Copy-on-Write)란?
?
fork 시 부모/자식이 같은 페이지 공유하다 쓰기 시점에만 복사.
exec를 바로 호출하면 복사 비용 0. Linux fork, STL, Redis 스냅샷 등에 활용.
<!--SR:!2026-05-27,1,230-->

DMA(Direct Memory Access)란?
?
CPU 개입 없이 I/O 장치↔메모리 직접 전송. CPU는 시작 주소/크기만 지정하고 다른 작업.
완료 시 인터럽트로 알림. CPU 사이클 절약, I/O 처리량↑.
<!--SR:!2026-05-27,1,230-->

시스템 콜(System Call)이란?
?
유저 모드 프로그램이 커널 서비스(파일 I/O, 프로세스, 네트워크)를 요청하는 인터페이스.
소프트웨어 인터럽트(trap)로 커널 모드 전환→처리→복귀. 모드 전환 비용 있어 최소화.
<!--SR:!2026-05-27,1,230-->

모놀리식 커널 vs 마이크로커널?
?
- 모놀리식: 커널 기능 전부 커널 공간. 빠름(함수 호출), 버그 영향 큼. Linux
- 마이크로커널: 최소 기능만 커널, 나머지 유저 서비스. IPC 느림, 안정·보안↑. QNX/seL4
<!--SR:!2026-05-27,1,230-->

RAID 레벨 요약?
?
0=스트라이핑(속도, 장애X), 1=미러링(안전, 용량50%),
5=분산패리티(1개 장애 허용, 최소3), 6=이중패리티(2개), 10=1+0(성능+안정).
<!--SR:!2026-05-27,1,230-->

inode란?
?
Unix/Linux에서 파일 메타데이터(크기·권한·타임스탬프·블록 포인터) 저장 구조.
파일명은 디렉터리가 inode 번호와 연결. 하드링크 = 같은 inode, 링크 카운트 0이면 삭제.
<!--SR:!2026-05-27,1,230-->

스핀락 vs 뮤텍스, 언제 무엇을?
?
- 스핀락: busy-wait, 컨텍스트 스위치 없음. 임계구역 짧을 때, 커널 ISR(sleep 불가)
- 뮤텍스: 락 없으면 sleep. 임계구역 길거나 I/O 포함 시. 단일코어선 스핀락 비효율
<!--SR:!2026-05-27,1,230-->

커널 모드 vs 유저 모드?
?
CPU 권한 레벨. 커널 모드 = 모든 명령/메모리 접근, 유저 모드 = 제한(특권 연산은 시스템 콜).
시스템 안정성·보안의 핵심. x86 Ring0~3, ARM EL0~3.
<!--SR:!2026-05-27,1,230-->

하드웨어 인터럽트 vs 소프트웨어 인터럽트?
?
- 하드웨어: I/O 완료·타이머·키보드 등 외부 장치가 비동기 발생
- 소프트웨어(trap/예외): 시스템 콜·0 나눗셈·페이지폴트 등 실행 중 동기 발생
<!--SR:!2026-05-27,1,230-->

PCB(Process Control Block)에 담기는 정보는?
?
PID/부모PID, CPU 상태(레지스터·PC·SP), 프로세스 상태,
메모리 정보(페이지 테이블), 스케줄링 정보(우선순위), 열린 파일 디스크립터.
<!--SR:!2026-05-27,1,230-->

파이프 vs 소켓?
?
- 파이프: 같은 호스트 관련 프로세스 간, 단/양방향, 주소 없음(`ls|grep`)
- 소켓: 네트워크 다른 호스트도 가능, 양방향, IP:Port 주소 지정
<!--SR:!2026-05-27,1,230-->

세그멘테이션 vs 페이징?
?
- 세그멘테이션: 논리 단위(코드/스택/힙) 분할, 외부 단편화 발생
- 페이징: 고정 크기, 외부 단편화 없음/내부 단편화 가능. 현대 OS 표준
<!--SR:!2026-05-27,1,230-->

페이지(Page)와 프레임(Frame)의 차이는?
?
페이지 = 가상 주소공간을 나눈 고정 단위, 프레임 = 물리 메모리를 나눈 같은 크기 단위.
페이지 테이블이 페이지 번호→프레임 번호로 매핑. 둘 크기 동일(보통 4KB).
<!--SR:!2026-05-27,1,230-->

워킹셋(Working Set) 모델이란?
?
프로세스가 특정 시간 구간 내 실제 참조한 페이지 집합.
워킹셋만큼 프레임 확보돼야 스래싱 없이 실행. OS가 추적해 메모리 할당량 동적 조절.
<!--SR:!2026-05-27,1,230-->

CFS(Completely Fair Scheduler)란?
?
Linux 기본 스케줄러. vruntime(가중 실행시간) 가장 작은 프로세스 선택.
Red-Black Tree로 O(log n). nice 값(-20~+19)으로 가중치, cgroups로 컨테이너 제한.
<!--SR:!2026-05-27,1,230-->

fork()와 exec()의 동작은?
?
- fork(): 프로세스 복사본 생성(부모엔 자식 PID, 자식엔 0). COW로 복사 지연
- exec(): 주소공간을 새 실행파일로 교체(PID 유지, FD 상속). 셸은 fork-exec 패턴
<!--SR:!2026-05-27,1,230-->
