# 그래픽스 출제 예상 토픽

## 1. 렌더링 파이프라인 (전체 단계)

```
IA (Input Assembler)
  ↓ 정점 데이터 모음 (VB, IB)
VS (Vertex Shader)
  ↓ 정점 변환 (Local→World→View→Clip)
[Tessellation Shader]  ← 옵션
  ↓ 정점 세분화
[Geometry Shader]      ← 옵션
  ↓ 정점 추가/삭제 (성능 부담 大)
Rasterization
  ↓ 정점 → 픽셀(프래그먼트) 변환
PS (Pixel/Fragment Shader)
  ↓ 픽셀 색상 계산
OM (Output Merger)
  ↓ Depth/Stencil 테스트, 블렌딩
Framebuffer
```

## 2. 좌표계 변환 (MVP)

```
Local space
  ↓ Model Matrix (M) — Translation/Rotation/Scale
World space
  ↓ View Matrix (V) — 카메라 기준 변환
View space
  ↓ Projection Matrix (P) — 원근/직교
Clip space
  ↓ Perspective Divide (w로 나누기)
NDC (Normalized Device Coords, -1~1)
  ↓ Viewport Transform
Screen space
```

전체 변환: `gl_Position = P × V × M × vertex`

## 3. 모바일 GPU (출제 핵심)

### TBR (Tile-Based Rendering)
- 화면을 작은 타일(예: 16x16, 32x32)로 분할 후 타일별 렌더
- 데스크탑은 **IMR** (Immediate Mode Rendering)
- **장점**: 타일 단위 처리 → 메모리 대역폭 절약 (모바일 핵심)
- **단점**: 정점 단계에서 Binning(타일 할당) 비용 추가

### TBDR (Tile-Based Deferred Rendering)
- PowerVR (애플 GPU), 일부 ARM Mali
- 타일 내에서 **HSR (Hidden Surface Removal)** 먼저 → Overdraw 최소화
- 픽셀 셰이더는 보이는 픽셀만 실행

### 통합 메모리 (Unified Memory)
- 모바일/콘솔: GPU/CPU가 메모리 공유 (복사 불필요)
- 데스크탑: GPU/CPU 메모리 분리 (PCIe 전송)
- 모바일은 메모리 대역폭이 성능 병목

### Overdraw
- 같은 픽셀이 여러 번 그려지는 현상
- 모바일에선 성능 직격타
- **해결**:
  1. 불투명 객체 앞→뒤 정렬 (Early Z 활용)
  2. **Z-prepass**: 깊이 먼저 그려서 픽셀 셰이더 실행 줄임
  3. 반투명 최소화

### 모바일 최적화 키워드
- Draw call 줄이기 (배칭)
- 텍스처 압축 (ETC2, ASTC)
- LOD (Level of Detail)
- 셰이더 단순화 (이미지 효과 최소화)

## 4. 그래픽스 API 비교

| API | 플랫폼 | 특징 |
|-----|--------|------|
| **DX12** | Windows / Xbox | MS 공식, 저수준, 멀티스레딩 강력 |
| **Vulkan** | Win/Linux/Android/Switch | 크로스, 오픈, 수동 메모리 관리 |
| **Metal** | iOS / macOS | Apple 전용, 효율적, 통합 메모리 친화 |
| **OpenGL ES** | 모바일 (레거시) | 고수준, 자동 관리 |
| **DX11 / OpenGL** | (레거시) | 고수준 |

**공통점 (저수준 API)**: 명시적 동기화, 수동 자원 관리, 멀티스레드 친화, 드라이버 오버헤드 감소

## 5. 셰이더 종류

| 셰이더 | 역할 | 빈도 |
|--------|------|------|
| Vertex Shader | 정점 변환 | 정점 수 |
| Tessellation | 정점 세분화 | 패치 수 |
| Geometry | 정점 추가/삭제 | 프리미티브 수 |
| Pixel/Fragment | 픽셀 색상 | 픽셀 수 (가장 많음) |
| Compute | 범용 GPU 연산 | 임의 |

## 6. 무게중심좌표 (Barycentric Coordinates)

```
P = αA + βB + γC,  단 α+β+γ=1
```

- 삼각형 ABC 내부 한 점 P를 가중치로 표현
- **용도**:
  - 정점 속성 보간 (UV, 색상, 법선)
  - 삼각형 내부 점 판정 (α,β,γ 모두 ≥ 0)
  - 텍스처 샘플링 좌표

## 7. 주요 텍스처 기술

- **Normal Map**: 표면 디테일 (법선 정보로 빛 계산 → 폴리곤 적게 써도 디테일)
- **Light Map**: 사전 계산된 정적 라이팅 (모바일 필수)
- **Shadow Map**: 광원 시점에서 본 Depth 텍스처 (그림자)
- **Cube Map**: 6면 텍스처 (환경맵, 스카이박스, 반사)
- **PBR**: 물리 기반 렌더링 (Albedo / Metallic / Roughness / Normal / AO)

## 8. 자주 묻는 개념

- **Z-Fighting**: 깊이 정밀도 부족 → 표면이 깜빡임
  - 해결: Near plane 멀리, 폴리곤 약간 오프셋, 로그 깊이 버퍼
- **Aliasing**: 계단 현상
  - MSAA / FXAA / TAA
- **MipMap**: 사전 축소 텍스처 → 거리별 자동 선택 (캐시 친화 + 모아레 방지)
- **Frustum Culling**: 시야 밖 객체 안 그림
- **Occlusion Culling**: 가려진 객체 안 그림
