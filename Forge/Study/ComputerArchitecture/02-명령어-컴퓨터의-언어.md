# Chapter 2: 명령어 — 컴퓨터의 언어 (Instructions: Language of the Computer)

## 1. RISC vs CISC 철학

> [!tip] 면접 빈출
> RISC vs CISC는 ISA 설계 철학의 근본 차이입니다. 단순 비교보다 **각 접근법의 트레이드오프**와 **현대 CPU에서 둘이 어떻게 혼합되는지** 설명할 수 있어야 합니다.

### 1.1 핵심 비교

| 항목 | RISC (Reduced Instruction Set Computer) | CISC (Complex Instruction Set Computer) |
|------|----------------------------------------|----------------------------------------|
| **대표 ISA** | RISC-V, ARM, MIPS | x86, x86-64 |
| **명령어 수** | 적음 (수십~100개 수준) | 많음 (수백~수천 개) |
| **명령어 길이** | 고정 (RISC-V: 32비트) | 가변 (x86: 1~15바이트) |
| **실행 사이클** | 대부분 1 사이클 | 명령어마다 다름 |
| **메모리 접근** | Load/Store 전용 명령어만 | 산술 명령어에서 직접 메모리 접근 가능 |
| **레지스터 수** | 많음 (32개 범용) | 적음 (x86: 8→16개) |
| **컴파일러** | 복잡 (레지스터 최적화 책임) | 단순 (하드웨어가 복잡성 흡수) |
| **하드웨어** | 단순 → 고속 파이프라이닝 유리 | 복잡 → 마이크로코드 필요 |

### 1.2 설계 원칙 (Design Principles)

P&H 교재에서 제시하는 RISC 설계 원칙 4가지:

> [!important] 4대 설계 원칙
> 1. **단순성은 규칙성을 선호한다** (Simplicity favors regularity) — 고정 길이 명령어, 3-operand 형식
> 2. **작을수록 빠르다** (Smaller is faster) — 레지스터 32개 (64개 아님), 적은 명령어 수
> 3. **좋은 설계는 적절한 타협을 요구한다** (Good design demands good compromises) — I-type의 즉치값 12비트
> 4. **자주 쓰이는 것을 빠르게** (Make the common case fast) — addi (즉치 덧셈)가 add보다 훨씬 자주 사용됨

### 1.3 현대 CPU에서의 융합

```
x86 CPU (Intel/AMD) 내부 구조:
┌─────────────────────────────────────────┐
│  x86 명령어 (CISC 인터페이스)             │
│              ↓ 디코더                    │
│  마이크로 연산 (μops, RISC-like)          │
│              ↓                          │
│  Out-of-Order 파이프라인 실행 엔진        │
└─────────────────────────────────────────┘
```

현대 x86은 CISC 인터페이스를 유지하면서 내부적으로 RISC-like μops로 분해하여 실행 → 외부 호환성 + 내부 효율성

## 2. RISC-V 레지스터 (Registers)

### 2.1 레지스터 개요

RISC-V는 **32개의 64비트 범용 레지스터** (RV64I 기준)를 제공합니다.

- 레지스터 이름: `x0` ~ `x31` (ABI 별칭도 사용)
- 64비트 레지스터: **doubleword** = 8 bytes
- 32비트 하위 절반: **word** = 4 bytes

> [!note] 왜 32개인가?
> 레지스터가 많을수록 더 많은 변수를 메모리 없이 보관할 수 있지만:
> - 레지스터 번호를 인코딩할 비트 수 증가 (32개 = 5비트)
> - 레지스터 파일 접근 속도 저하 (물리적 거리 증가)
> - 컨텍스트 스위칭 비용 증가
> → 32개가 성능/비용의 적절한 균형점

### 2.2 레지스터 분류표 (ABI 규약)

| 레지스터 | ABI 이름 | 역할 | Caller/Callee Saved |
|---------|---------|------|---------------------|
| `x0` | `zero` | 항상 0 (하드와이어드, 쓰기 무시) | — |
| `x1` | `ra` | Return Address (반환 주소) | **Caller** saved |
| `x2` | `sp` | Stack Pointer (스택 포인터) | **Callee** saved |
| `x3` | `gp` | Global Pointer (전역 포인터) | — |
| `x4` | `tp` | Thread Pointer (스레드 포인터) | — |
| `x5` | `t0` | Temporary / 링크 레지스터 | **Caller** saved |
| `x6-x7` | `t1-t2` | Temporary (임시 값) | **Caller** saved |
| `x8` | `s0/fp` | Saved / Frame Pointer | **Callee** saved |
| `x9` | `s1` | Saved Register | **Callee** saved |
| `x10-x11` | `a0-a1` | 함수 인자 & 반환값 | **Caller** saved |
| `x12-x17` | `a2-a7` | 함수 인자 | **Caller** saved |
| `x18-x27` | `s2-s11` | Saved Registers | **Callee** saved |
| `x28-x31` | `t3-t6` | Temporary | **Caller** saved |

> [!tip] 암기 요령
> - **`s` 레지스터** (s0-s11) → "**S**aved" → **Callee**가 보존 책임
> - **`t` 레지스터** (t0-t6) → "**T**emporary" → **Caller**가 저장해야 함
> - **`a` 레지스터** (a0-a7) → "**A**rgument" → **Caller** saved (호출 후 변할 수 있음)

## 3. 명령어 형식 (Instruction Formats)

RISC-V의 모든 명령어는 **32비트 고정 길이**입니다. 6가지 형식이 있습니다.

### 3.1 R-type (Register)

산술/논리 연산: `rd = rs1 op rs2`

```
 31      25 24   20 19   15 14  12 11    7 6       0
┌──────────┬───────┬───────┬──────┬───────┬─────────┐
│  funct7  │  rs2  │  rs1  │funct3│  rd   │ opcode  │
│  7 bits  │5 bits │5 bits │3 bits│5 bits │ 7 bits  │
└──────────┴───────┴───────┴──────┴───────┴─────────┘
```

- `opcode`: 명령어 종류 대분류
- `funct3` + `funct7`: 세부 연산 구분
- 예: `add x1, x2, x3` → x1 = x2 + x3

### 3.2 I-type (Immediate)

즉치값 연산, 로드 명령어: `rd = rs1 op imm`

```
 31         20 19   15 14  12 11    7 6       0
┌─────────────┬───────┬──────┬───────┬─────────┐
│  imm[11:0]  │  rs1  │funct3│  rd   │ opcode  │
│   12 bits   │5 bits │3 bits│5 bits │ 7 bits  │
└─────────────┴───────┴──────┴───────┴─────────┘
```

- `imm[11:0]`: 12비트 부호 있는 즉치값 → **−2048 ~ 2047** 범위
- 예: `addi x1, x2, 100` → x1 = x2 + 100
- 예: `lw x1, 8(x2)` → x1 = Memory[x2 + 8]

### 3.3 S-type (Store)

스토어 명령어: `Memory[rs1 + imm] = rs2`

```
 31      25 24   20 19   15 14  12 11    7 6       0
┌──────────┬───────┬───────┬──────┬───────┬─────────┐
│imm[11:5] │  rs2  │  rs1  │funct3│imm[4:0]│ opcode │
│  7 bits  │5 bits │5 bits │3 bits│5 bits │ 7 bits  │
└──────────┴───────┴───────┴──────┴───────┴─────────┘
```

- 즉치값이 두 필드에 분할 저장 → 레지스터 필드 위치를 R/I-type과 통일하기 위함
- 예: `sw x1, 8(x2)` → Memory[x2 + 8] = x1

### 3.4 B-type (Branch)

조건 분기: `if (rs1 op rs2) PC += imm`

```
 31      25 24   20 19   15 14  12 11       7 6       0
┌──────────┬───────┬───────┬──────┬──────────┬─────────┐
│imm[12|10:5]│rs2  │  rs1  │funct3│imm[4:1|11]│ opcode │
│  7 bits  │5 bits │5 bits │3 bits│  5 bits  │ 7 bits  │
└──────────┴───────┴───────┴──────┴──────────┴─────────┘
```

- 즉치값 인코딩: `imm[12|10:5|4:1|11]` — 비트 순서가 특수함
- **imm[0]은 항상 0** (명령어는 2바이트 정렬) → 실제 오프셋 범위: **±4KB**
- 예: `beq x1, x2, label` → if (x1 == x2) PC = PC + offset

### 3.5 U-type (Upper Immediate)

상위 20비트 즉치값 명령어

```
 31                12 11    7 6       0
┌────────────────────┬───────┬─────────┐
│     imm[31:12]     │  rd   │ opcode  │
│      20 bits       │5 bits │ 7 bits  │
└────────────────────┴───────┴─────────┘
```

- `lui` (Load Upper Immediate): `rd = imm << 12`
- `auipc` (Add Upper Immediate to PC): `rd = PC + (imm << 12)`
- 32비트 이상의 상수 로드 시 `lui` + `addi` 조합 사용

### 3.6 J-type (Jump)

무조건 점프: `rd = PC + 4; PC += imm`

```
 31                                    12 11    7 6       0
┌─────────────────────────────────────────┬───────┬─────────┐
│      imm[20|10:1|11|19:12]              │  rd   │ opcode  │
│               20 bits                  │5 bits │ 7 bits  │
└─────────────────────────────────────────┴───────┴─────────┘
```

- `jal` (Jump And Link): `rd = PC+4; PC = PC + imm` — **±1MB** 범위
- `jalr` (Jump And Link Register, I-type): `rd = PC+4; PC = (rs1 + imm) & ~1`
- `ra`(x1)에 반환 주소 저장하는 것이 관례

### 3.7 형식 비교 요약

| 형식 | 용도 | rs1 | rs2 | rd | imm 크기 |
|------|------|:---:|:---:|:--:|:-------:|
| **R** | 레지스터 산술/논리 | O | O | O | — |
| **I** | 즉치 산술, 로드, jalr | O | — | O | 12비트 |
| **S** | 스토어 | O | O | — | 12비트 |
| **B** | 조건 분기 | O | O | — | 13비트(±4KB) |
| **U** | lui, auipc | — | — | O | 20비트 |
| **J** | jal | — | — | O | 21비트(±1MB) |

## 4. 명령어 종류 (Instruction Set)

### 4.1 산술 명령어 (Arithmetic)

```asm
# 레지스터-레지스터 (R-type)
add  rd, rs1, rs2    # rd = rs1 + rs2
sub  rd, rs1, rs2    # rd = rs1 - rs2
mul  rd, rs1, rs2    # rd = (rs1 * rs2)[63:0]   (M 확장)
div  rd, rs1, rs2    # rd = rs1 / rs2  (부호 있는, M 확장)
rem  rd, rs1, rs2    # rd = rs1 % rs2  (M 확장)

# 즉치값 (I-type)
addi rd, rs1, imm    # rd = rs1 + SignExt(imm)
# subi 없음 → addi rd, rs1, -imm 사용
```

### 4.2 논리 명령어 (Logical)

```asm
# 레지스터-레지스터
and  rd, rs1, rs2    # rd = rs1 & rs2  (비트 AND)
or   rd, rs1, rs2    # rd = rs1 | rs2  (비트 OR)
xor  rd, rs1, rs2    # rd = rs1 ^ rs2  (비트 XOR)

# 즉치값
andi rd, rs1, imm    # rd = rs1 & SignExt(imm)
ori  rd, rs1, imm    # rd = rs1 | SignExt(imm)
xori rd, rs1, imm    # rd = rs1 ^ SignExt(imm)

# 시프트
sll  rd, rs1, rs2    # rd = rs1 << rs2  (논리 좌시프트)
srl  rd, rs1, rs2    # rd = rs1 >> rs2  (논리 우시프트, 0 채움)
sra  rd, rs1, rs2    # rd = rs1 >> rs2  (산술 우시프트, 부호 채움)
slli rd, rs1, imm    # rd = rs1 << imm  (즉치)
srli rd, rs1, imm    # rd = rs1 >> imm  (논리, 즉치)
srai rd, rs1, imm    # rd = rs1 >> imm  (산술, 즉치)
```

### 4.3 메모리 접근 명령어 (Memory Access)

RISC-V는 **Load/Store 아키텍처** — 메모리 데이터는 반드시 레지스터에 로드 후 연산

```asm
# 로드 (I-type)
lb   rd, imm(rs1)   # rd = SignExt(Mem[rs1+imm][7:0])   (1바이트, 부호)
lh   rd, imm(rs1)   # rd = SignExt(Mem[rs1+imm][15:0])  (2바이트, 부호)
lw   rd, imm(rs1)   # rd = SignExt(Mem[rs1+imm][31:0])  (4바이트, 부호)
ld   rd, imm(rs1)   # rd = Mem[rs1+imm][63:0]           (8바이트)
lbu  rd, imm(rs1)   # rd = ZeroExt(Mem[rs1+imm][7:0])  (부호 없음)
lhu  rd, imm(rs1)   # rd = ZeroExt(Mem[rs1+imm][15:0]) (부호 없음)
lwu  rd, imm(rs1)   # rd = ZeroExt(Mem[rs1+imm][31:0]) (부호 없음)

# 스토어 (S-type)
sb   rs2, imm(rs1)  # Mem[rs1+imm][7:0]  = rs2[7:0]
sh   rs2, imm(rs1)  # Mem[rs1+imm][15:0] = rs2[15:0]
sw   rs2, imm(rs1)  # Mem[rs1+imm][31:0] = rs2[31:0]
sd   rs2, imm(rs1)  # Mem[rs1+imm][63:0] = rs2[63:0]
```

> [!warning] 정렬 요구사항 (Alignment)
> RISC-V 기본 사양에서 `lw`/`sw`는 4바이트 정렬, `ld`/`sd`는 8바이트 정렬을 권장합니다.
> 비정렬 접근은 예외(exception)를 발생시킬 수 있습니다.

### 4.4 비교 및 분기 명령어 (Compare & Branch)

```asm
# 조건 분기 (B-type) — PC-relative 주소
beq  rs1, rs2, label  # if (rs1 == rs2) goto label
bne  rs1, rs2, label  # if (rs1 != rs2) goto label
blt  rs1, rs2, label  # if (rs1 <  rs2) goto label  (부호 있는)
bge  rs1, rs2, label  # if (rs1 >= rs2) goto label  (부호 있는)
bltu rs1, rs2, label  # if (rs1 <  rs2) goto label  (부호 없는)
bgeu rs1, rs2, label  # if (rs1 >= rs2) goto label  (부호 없는)

# 비교 후 레지스터에 저장 (R/I-type)
slt  rd, rs1, rs2     # rd = (rs1 < rs2) ? 1 : 0  (부호 있는)
sltu rd, rs1, rs2     # rd = (rs1 < rs2) ? 1 : 0  (부호 없는)
slti rd, rs1, imm     # rd = (rs1 < imm) ? 1 : 0
sltiu rd, rs1, imm    # rd = (rs1 < imm) ? 1 : 0  (부호 없는)
```

### 4.5 점프 명령어 (Jump)

```asm
# 무조건 점프 (J-type)
jal  rd, label        # rd = PC+4; PC = PC + offset   (±1MB)
# 관례: jal x0, label → 반환 주소 불필요한 jump (pseudo: j label)
# 관례: jal ra, label → 함수 호출 (pseudo: call label)

# 레지스터 기반 점프 (I-type)
jalr rd, imm(rs1)     # rd = PC+4; PC = (rs1+imm) & ~1
# 관례: jalr x0, 0(ra) → 함수 반환 (pseudo: ret)
```

### 4.6 상수 로드 명령어

```asm
lui  rd, imm          # rd = imm << 12  (상위 20비트 로드)
auipc rd, imm         # rd = PC + (imm << 12)  (PC 상대 주소)

# 32비트 상수 로드 예: 0xDEADBEEF
lui  x1, 0xDEADB      # x1 = 0xDEADB000
addi x1, x1, 0xEEF    # 주의: 0xEEF = -273 (부호 있는 12비트)
# → 실제로는 lui의 상위값을 +1 조정 필요할 수 있음
```

> [!warning] lui + addi 함정
> addi의 즉치값은 **부호 있는 12비트**입니다. 하위 12비트가 `0x800` 이상이면 음수로 해석되어 lui 값에서 1을 빼게 됩니다.
> 예: 상수 `0x12345678` 로드 시 하위 12비트 `0x678` = 1656 (양수) → 안전
> 상수 `0x12345ABC` 로드 시 하위 12비트 `0xABC` = -1348 (음수) → lui에 +1 필요

## 5. 의사 명령어 (Pseudo-Instructions)

어셈블러가 실제 명령어 하나 이상으로 변환해주는 편의 명령어입니다.

| 의사 명령어 | 실제 변환 | 설명 |
|------------|----------|------|
| `nop` | `addi x0, x0, 0` | 아무것도 안함 |
| `li rd, imm` | `lui`+`addi` 또는 `addi x0, imm` | 즉치값 로드 |
| `mv rd, rs` | `addi rd, rs, 0` | 레지스터 복사 |
| `not rd, rs` | `xori rd, rs, -1` | 비트 반전 |
| `neg rd, rs` | `sub rd, x0, rs` | 2의 보수 |
| `j label` | `jal x0, label` | 무조건 점프 (반환 X) |
| `call label` | `auipc ra, offset[31:12]` + `jalr ra, offset[11:0](ra)` | 함수 호출 |
| `ret` | `jalr x0, 0(ra)` | 함수 반환 |
| `beqz rs, label` | `beq rs, x0, label` | 0이면 분기 |
| `bnez rs, label` | `bne rs, x0, label` | 0이 아니면 분기 |
| `bgt rs1, rs2, label` | `blt rs2, rs1, label` | 크면 분기 |
| `ble rs1, rs2, label` | `bge rs2, rs1, label` | 작거나 같으면 분기 |
| `seqz rd, rs` | `sltiu rd, rs, 1` | rs==0이면 rd=1 |
| `snez rd, rs` | `sltu rd, x0, rs` | rs!=0이면 rd=1 |
| `la rd, symbol` | `auipc`+`addi` | 심볼 주소 로드 |

## 6. 어드레싱 모드 (Addressing Modes)

RISC-V가 지원하는 4가지 어드레싱 모드:

| 모드 | 예시 | 유효 주소 / 값 | 설명 |
|------|------|--------------|------|
| **즉치 (Immediate)** | `addi x1, x2, 100` | 100 (값 그 자체) | 상수값 직접 사용 |
| **레지스터 (Register)** | `add x1, x2, x3` | x3의 값 | 레지스터 값 직접 사용 |
| **베이스+오프셋 (Base+Offset)** | `lw x1, 8(x2)` | Mem[x2 + 8] | 레지스터+상수 주소 |
| **PC 상대 (PC-Relative)** | `beq x1, x2, L` | PC + offset | 현재 PC 기준 분기 |

> [!note] x86과의 차이
> x86은 스케일 인덱스, 세그먼트 등 복잡한 어드레싱 모드를 지원하지만, RISC-V는 Base+Offset 하나만으로 단순화합니다. 배열 접근은 컴파일러가 인덱스 계산을 명시적으로 수행합니다.

## 7. 프로시저 호출 규약 (Procedure Calling Convention)

### 7.1 Caller / Callee Saved 레지스터

프로시저 호출 전후 레지스터 보존 책임을 분담합니다.

| 구분 | 레지스터 | 책임자 | 의미 |
|------|---------|-------|------|
| **Caller Saved** | `ra, t0-t6, a0-a7` | **호출자(Caller)** | 함수 호출 전 필요시 스택에 저장 |
| **Callee Saved** | `sp, s0-s11` | **피호출자(Callee)** | 함수 내에서 사용 시 복원 의무 |

```
Caller Saved (일시적):
  - 함수 호출 시 덮어써질 수 있음
  - 호출자가 필요하면 call 전에 직접 저장

Callee Saved (보존):
  - 함수가 사용하려면 먼저 저장하고, 반환 전 복원
  - 호출자 입장에서 "call 전후 값이 같음" 보장
```

### 7.2 스택 프레임 구조 (Stack Frame)

RISC-V 스택은 **높은 주소에서 낮은 주소로 성장** (스택 포인터 `sp`가 감소)

```
높은 주소
┌─────────────────────────┐  ← 이전 함수의 sp
│  Caller의 스택 프레임    │
│  (caller saved regs...)  │
├─────────────────────────┤  ← 현재 함수 진입 시 sp
│  ra (반환 주소)          │  ← sp + frame_size - 8
├─────────────────────────┤
│  s0 (fp, 이전 프레임 포인터)│
├─────────────────────────┤
│  s1-s11 (저장된 레지스터) │
├─────────────────────────┤
│  지역 변수               │
├─────────────────────────┤
│  임시 값                 │
└─────────────────────────┘  ← 현재 sp (함수 실행 중)
낮은 주소
```

### 7.3 프로시저 호출 단계

```asm
# ========== Caller ==========
# 1. 인자를 a0-a7에 배치
# 2. 필요시 caller-saved 레지스터 저장
# 3. jal ra, function  (호출)
# 4. 반환 후 a0/a1에서 반환값 읽기
# 5. 저장했던 caller-saved 레지스터 복원

# ========== Callee (함수 프롤로그) ==========
function:
    addi sp, sp, -32        # 스택 프레임 할당 (예: 32바이트)
    sd   ra, 24(sp)         # ra 저장 (중첩 호출 시 필수)
    sd   s0, 16(sp)         # s0 저장 (사용할 경우)
    addi s0, sp, 32         # fp = sp + frame_size

    # ... 함수 본체 ...
    # 반환값을 a0 (또는 a0, a1)에 저장

# ========== 에필로그 ==========
    ld   ra, 24(sp)         # ra 복원
    ld   s0, 16(sp)         # s0 복원
    addi sp, sp, 32         # 스택 해제
    jalr x0, 0(ra)          # 반환 (= ret)
```

### 7.4 인자 전달 규약

- **8개 이하 인자**: `a0`~`a7` 사용 (정수/포인터)
- **9개 이상 인자**: 초과분은 스택에 저장 (sp 기준)
- **반환값**: `a0` (1개) 또는 `a0, a1` (2개, 64비트 구조체 등)
- **구조체 전달**: 작은 구조체(≤2 레지스터)는 레지스터, 큰 구조체는 포인터 전달

## 8. 기계어 ↔ 어셈블리 변환

### 8.1 어셈블리 → 기계어 변환 예시

#### 예시 1: `add x9, x20, x21`

| 필드 | 값 | 비트 수 | 이진수 |
|------|---|---------|--------|
| funct7 | 0 | 7 | `0000000` |
| rs2 | x21 = 21 | 5 | `10101` |
| rs1 | x20 = 20 | 5 | `10100` |
| funct3 | 0 | 3 | `000` |
| rd | x9 = 9 | 5 | `01001` |
| opcode | 0110011 | 7 | `0110011` |

$$\text{기계어} = \underbrace{0000000}_{funct7}\underbrace{10101}_{rs2}\underbrace{10100}_{rs1}\underbrace{000}_{funct3}\underbrace{01001}_{rd}\underbrace{0110011}_{opcode}$$

= `0x01594433` (16진수)

#### 예시 2: `lw x9, 64(x22)` (I-type)

| 필드 | 값 | 비트 수 | 이진수 |
|------|---|---------|--------|
| imm[11:0] | 64 | 12 | `000001000000` |
| rs1 | x22 = 22 | 5 | `10110` |
| funct3 | 2 (lw) | 3 | `010` |
| rd | x9 = 9 | 5 | `01001` |
| opcode | 0000011 | 7 | `0000011` |

$$\text{기계어} = \underbrace{000001000000}_{imm}\underbrace{10110}_{rs1}\underbrace{010}_{funct3}\underbrace{01001}_{rd}\underbrace{0000011}_{opcode}$$

= `0x040B2483`

### 8.2 기계어 → 어셈블리 변환 예시

기계어 `0x00A50533` 분석:

```
0x00A50533 = 0000 0000 1010 0101 0000 0101 0011 0011

비트 분해:
  [31:25] = 0000000  → funct7 = 0
  [24:20] = 01010    → rs2 = 10 (x10 = a0)
  [19:15] = 01010    → rs1 = 10 (x10 = a0)  ← 오류, 다시:
```

실제 올바른 분석:
```
0x00A50533:
  bits[6:0]   = 0110011 → R-type (산술)
  bits[11:7]  = 01010   → rd = x10
  bits[14:12] = 000     → funct3 = 0 (add)
  bits[19:15] = 01010   → rs1 = x10
  bits[24:20] = 01010   → rs2 = x10
  bits[31:25] = 0000000 → funct7 = 0

→ add x10, x10, x10  (a0 = a0 + a0, 즉 a0 *= 2)
```

## 9. C → RISC-V 어셈블리 변환

### 9.1 배열 접근

```c
// C 코드
int A[100];
A[i] = A[i+1];
// i는 x19, A의 기주소는 x22에 있다고 가정
```

```asm
# RISC-V 어셈블리
slli x10, x19, 2      # x10 = i * 4 (int = 4바이트)
add  x10, x10, x22   # x10 = &A[i]
lw   x9,  4(x10)     # x9  = A[i+1]  (오프셋 +4)
sw   x9,  0(x10)     # A[i] = x9
```

### 9.2 if-else 문

```c
// C 코드
if (i == j)
    f = g + h;
else
    f = g - h;
// f=x19, g=x20, h=x21, i=x22, j=x23
```

```asm
# RISC-V 어셈블리
      bne  x22, x23, Else    # if (i != j) goto Else
      add  x19, x20, x21    # f = g + h
      beq  x0,  x0,  Exit   # goto Exit (j 의사명령어 가능)
Else: sub  x19, x20, x21    # f = g - h
Exit: ...
```

### 9.3 while 루프

```c
// C 코드
while (save[i] == k)
    i += 1;
// i=x22, k=x24, save 기주소=x25
```

```asm
# RISC-V 어셈블리
Loop: slli x10, x22, 2      # x10 = i * 4
      add  x10, x10, x25   # x10 = &save[i]
      lw   x9,  0(x10)     # x9  = save[i]
      bne  x9,  x24, Exit  # if (save[i] != k) break
      addi x22, x22, 1     # i++
      beq  x0,  x0,  Loop  # goto Loop
Exit: ...
```

### 9.4 재귀 함수 (팩토리얼)

```c
// C 코드
long long int fact(long long int n) {
    if (n < 1) return 1;
    else return n * fact(n-1);
}
```

```asm
# RISC-V 어셈블리
fact:
    addi sp, sp, -16     # 스택 프레임 16바이트 할당
    sd   ra, 8(sp)       # ra 저장 (재귀 호출 있으므로 필수)
    sd   a0, 0(sp)       # n 저장

    addi t0, x0, 1
    bge  a0, t0, L1      # if (n >= 1) goto L1
    addi a0, x0, 1       # n < 1: 반환값 = 1
    addi sp, sp, 16
    jalr x0, 0(ra)       # ret

L1: addi a0, a0, -1      # a0 = n - 1
    jal  ra, fact        # fact(n-1)
    ld   t1, 0(sp)       # t1 = n (저장해뒀던 값)
    mul  a0, t1, a0      # a0 = n * fact(n-1)
    ld   ra, 8(sp)       # ra 복원
    addi sp, sp, 16      # 스택 해제
    jalr x0, 0(ra)       # ret
```

## 10. 엔디안 (Endianness)

### 10.1 빅 엔디안 vs 리틀 엔디안

메모리에 다중 바이트 값을 저장하는 방식:

```
값: 0xA1B2C3D4 (32비트)

빅 엔디안 (Big-Endian):   MSB가 낮은 주소
주소: 100  101  102  103
값:   A1   B2   C3   D4
      ↑ 최상위 바이트(MSB)

리틀 엔디안 (Little-Endian):  LSB가 낮은 주소
주소: 100  101  102  103
값:   D4   C3   B2   A1
      ↑ 최하위 바이트(LSB)
```

| | 빅 엔디안 | 리틀 엔디안 |
|--|---------|-----------|
| **사용처** | 네트워크 프로토콜, SPARC, PowerPC | x86, ARM, **RISC-V** |
| **장점** | 사람이 읽기 쉬움, 직렬 비교 가능 | 타입 캐스팅 용이 (하위 주소 = 하위 바이트) |
| **단점** | 타입 캐스팅 불편 | 디버깅 시 바이트 역순으로 보임 |

> [!tip] 면접 팁
> RISC-V는 **리틀 엔디안**입니다. 네트워크 데이터(빅 엔디안 = Network Byte Order) 처리 시 `ntohl()`, `htonl()` 등 변환 함수가 필요한 이유입니다.

## 11. 면접 Q&A (12개+)

> [!faq] Q1. RISC와 CISC의 핵심 차이는 무엇인가요?
> **A**: RISC는 단순하고 고정 길이의 명령어를 사용하여 하드웨어를 단순화하고 파이프라이닝을 용이하게 합니다. CISC는 복잡하고 가변 길이 명령어를 제공하여 코드 밀도를 높이고 프로그래머 편의를 증가시킵니다.
> 현대 x86 CPU는 CISC 인터페이스를 유지하면서 내부적으로 RISC-like 마이크로 연산(μops)으로 변환하여 실행합니다.

> [!faq] Q2. RISC-V에서 레지스터가 32개인 이유는?
> **A**: 레지스터 수는 **성능과 비용의 트레이드오프**입니다.
> - 레지스터가 많을수록 더 많은 변수를 캐시처럼 보관 가능 (메모리 접근 감소)
> - 그러나 레지스터 번호 인코딩에 더 많은 비트 필요 (32개 = 5비트, 명령어 공간 감소)
> - 레지스터 파일이 커질수록 접근 속도 저하 (물리적 거리, 포트 수)
> - 컨텍스트 스위칭 시 저장/복원 비용 증가
> 32개는 이 트레이드오프의 균형점으로 실험적으로 검증된 값입니다.

> [!faq] Q3. x0 레지스터를 항상 0으로 고정하는 이유는?
> **A**: `x0 = 0` 하드와이어링은 여러 유용한 패턴을 단순화합니다:
> - `add rd, x0, rs` → `mv rd, rs` (레지스터 복사)
> - `sub rd, x0, rs` → `neg rd, rs` (부호 반전)
> - `beq rs, x0, label` → `beqz rs, label` (0과 비교 분기)
> - `addi x0, x0, 0` → `nop`
> 별도의 `move`나 `clear` 명령어 없이도 이 기능들을 구현할 수 있어 명령어 세트를 단순화합니다.

> [!faq] Q4. Caller-Saved vs Callee-Saved 레지스터의 차이와 왜 두 가지로 나누나요?
> **A**:
> - **Caller-Saved**: 함수를 호출하는 쪽이 보존 책임. 호출 후 값이 바뀔 수 있으므로, 필요하면 call 전에 스택에 저장해야 합니다. (`t0-t6`, `a0-a7`, `ra`)
> - **Callee-Saved**: 호출받는 함수가 보존 책임. 함수 내에서 사용하려면 먼저 저장하고 반환 전 복원해야 합니다. (`s0-s11`, `sp`)
>
> 두 종류로 나누는 이유: 모든 레지스터를 매번 저장하면 불필요한 오버헤드 발생. 분업을 통해 실제로 필요한 레지스터만 저장하도록 최적화.

> [!faq] Q5. 스택 프레임(Stack Frame)이란 무엇이고 어떤 정보가 포함되나요?
> **A**: 스택 프레임(또는 activation record)은 함수 호출 시 스택에 할당되는 메모리 영역입니다. 포함 정보:
> 1. **반환 주소(ra)**: 함수 완료 후 돌아갈 주소 (중첩 호출 시 필수 저장)
> 2. **Callee-saved 레지스터**: 함수가 사용할 s0-s11
> 3. **지역 변수**: 레지스터에 담을 수 없는 지역 변수
> 4. **인자 오버플로우**: 8개 이상의 함수 인자
> 5. **프레임 포인터(fp/s0)**: 현재 프레임의 기준점 (선택적)
>
> RISC-V 스택은 높은 주소→낮은 주소 방향으로 성장합니다.

> [!faq] Q6. 즉치값(Immediate)의 범위가 12비트인데 더 큰 상수는 어떻게 로드하나요?
> **A**: `lui` + `addi` 조합을 사용합니다.
> - `lui rd, upper20`: 상위 20비트를 rd에 로드 (rd = upper20 << 12)
> - `addi rd, rd, lower12`: 하위 12비트 추가
> 주의: `addi`의 즉치값은 부호 있는 12비트이므로, 하위 12비트 ≥ 0x800이면 `lui`의 값을 +1 해야 합니다 (음수 연산 보정). 어셈블러는 이를 자동으로 처리합니다.

> [!faq] Q7. B-type 명령어에서 imm[0]이 없는 이유는?
> **A**: RISC-V 명령어는 최소 2바이트 정렬(기본 ISA는 4바이트)을 보장합니다. 따라서 분기 오프셋의 최하위 비트는 항상 0입니다. 이를 인코딩에서 생략하여 **1비트를 절약**하고, 동일한 13비트 즉치값 필드로 ±4KB 범위(12비트 + 1비트 절약)를 표현합니다. 실제 오프셋은 `imm << 1`로 계산됩니다.

> [!faq] Q8. RISC-V에서 bgt나 ble 명령어가 없는 이유는?
> **A**: `bgt rs1, rs2, label`은 `blt rs2, rs1, label`과 동일합니다 (오퍼랜드 순서 교환). RISC 원칙에 따라 중복 명령어를 제거하여 하드웨어를 단순화합니다. 어셈블러가 의사 명령어로 자동 변환합니다.

> [!faq] Q9. Little-Endian과 Big-Endian의 차이와 RISC-V는 어느 쪽인가요?
> **A**: 다중 바이트 데이터를 메모리에 저장할 때 바이트 순서의 차이입니다.
> - **Little-Endian**: LSB(최하위 바이트)가 낮은 주소. x86, ARM, **RISC-V** 사용.
> - **Big-Endian**: MSB(최상위 바이트)가 낮은 주소. 네트워크 프로토콜(TCP/IP) 표준.
>
> 실무 영향: 네트워크 데이터를 RISC-V에서 처리하려면 바이트 순서 변환 필요 (`ntohl` 등). 파일 포맷, 프로토콜 설계 시 엔디안 명시 필수.

> [!faq] Q10. jal과 jalr의 차이는?
> **A**:
> - `jal rd, offset`: J-type. PC + 부호확장된 21비트 offset으로 점프. **±1MB** 범위. PC 상대 주소라 위치 독립적(PIC). 함수 호출에 주로 사용.
> - `jalr rd, imm(rs1)`: I-type. (rs1 + imm) & ~1로 점프. 레지스터 값을 기반으로 임의 주소 점프 가능. **함수 포인터, 가상 함수, 반환(ret)** 등에 사용.
>
> `ret`은 `jalr x0, 0(ra)`의 의사 명령어입니다.

> [!faq] Q11. 어떤 경우에 auipc가 필요한가요?
> **A**: `auipc rd, imm`은 `rd = PC + (imm << 12)`를 계산합니다. 사용 사례:
> 1. **위치 독립 코드(PIC/PIE)**: 실행 시 로드 주소를 모를 때 PC 상대 주소 계산
> 2. **큰 PC 상대 오프셋**: `jal`의 ±1MB를 넘는 먼 거리 점프 (`auipc` + `jalr` 조합)
> 3. **전역 변수 주소 로드**: `la` 의사 명령어가 `auipc + addi`로 변환됨

> [!faq] Q12. 함수에서 ra(x1)를 스택에 저장하는 경우는 언제인가요?
> **A**: **Leaf 함수(더 이상 함수를 호출하지 않는 함수)** 는 `ra`를 저장할 필요가 없습니다. 하지만 **Non-Leaf 함수(다른 함수를 호출하는 함수)** 는 반드시 저장해야 합니다. `jal ra, callee` 실행 시 `ra`가 다음 명령어 주소로 덮어써지기 때문입니다. 재귀 함수는 항상 Non-Leaf이므로 `ra` 저장이 필수입니다.

> [!faq] Q13. R-type 명령어에 funct7 필드가 필요한 이유는?
> **A**: opcode(7비트) + funct3(3비트)만으로는 구분할 수 없는 명령어들이 있기 때문입니다. 예를 들어 `add`와 `sub`는 opcode와 funct3이 같고, funct7로만 구분됩니다 (`add`: funct7=0000000, `sub`: funct7=0100000). `srl`과 `sra`도 마찬가지입니다. funct7은 또한 향후 확장을 위한 공간을 제공합니다.

### 문제 7: 재귀 → 반복 변환

피보나치 수를 재귀로 구현한 RISC-V 어셈블리를 **반복 버전**으로 재작성하라.

```c
// 재귀 버전
int fib(int n) {
    if (n <= 1) return n;
    return fib(n-1) + fib(n-2);
}
```

<details>
<summary>풀이 보기</summary>

```c
// 반복 버전 (C)
int fib(int n) {
    if (n <= 1) return n;
    int a = 0, b = 1, c;
    for (int i = 2; i <= n; i++) {
        c = a + b;
        a = b;
        b = c;
    }
    return b;
}
```

```asm
# RISC-V 반복 버전
# 인자: a0 = n, 반환: a0
fib:
    li   t0, 1
    ble  a0, t0, Done    # if (n <= 1) return n

    li   t1, 0           # a = 0
    li   t2, 1           # b = 1
    li   t3, 2           # i = 2

Loop:
    bgt  t3, a0, End     # if (i > n) goto End
    add  t4, t1, t2      # c = a + b
    mv   t1, t2          # a = b
    mv   t2, t4          # b = c
    addi t3, t3, 1       # i++
    j    Loop

End:
    mv   a0, t2          # 반환값 = b
    ret
Done:
    ret                  # n <= 1이면 a0(=n) 그대로 반환
```

스택 프레임 불필요 → Leaf function → ra 저장 불필요 → 효율적
</details>

## 13. RISC-V 명령어 레퍼런스 카드

### 13.1 산술/논리 명령어

| 명령어 | 형식 | 동작 | 예제 |
|--------|------|------|------|
| `add` | R | rd = rs1 + rs2 | `add x1, x2, x3` |
| `sub` | R | rd = rs1 - rs2 | `sub x1, x2, x3` |
| `addi` | I | rd = rs1 + imm | `addi x1, x2, 10` |
| `mul` | R | rd = rs1 × rs2 (하위 64비트) | `mul x1, x2, x3` |
| `div` | R | rd = rs1 ÷ rs2 (부호) | `div x1, x2, x3` |
| `rem` | R | rd = rs1 % rs2 (부호) | `rem x1, x2, x3` |
| `and` | R | rd = rs1 & rs2 | `and x1, x2, x3` |
| `or` | R | rd = rs1 \| rs2 | `or x1, x2, x3` |
| `xor` | R | rd = rs1 ^ rs2 | `xor x1, x2, x3` |
| `andi` | I | rd = rs1 & imm | `andi x1, x2, 0xFF` |
| `ori` | I | rd = rs1 \| imm | `ori x1, x2, 1` |
| `xori` | I | rd = rs1 ^ imm | `xori x1, x2, -1` |
| `sll` | R | rd = rs1 << rs2 | `sll x1, x2, x3` |
| `srl` | R | rd = rs1 >> rs2 (논리) | `srl x1, x2, x3` |
| `sra` | R | rd = rs1 >> rs2 (산술) | `sra x1, x2, x3` |
| `slli` | I | rd = rs1 << imm | `slli x1, x2, 4` |
| `srli` | I | rd = rs1 >> imm (논리) | `srli x1, x2, 4` |
| `srai` | I | rd = rs1 >> imm (산술) | `srai x1, x2, 4` |

### 13.2 메모리 접근 명령어

| 명령어 | 형식 | 동작 | 예제 |
|--------|------|------|------|
| `lb` | I | rd = SignExt(Mem[rs1+imm][7:0]) | `lb x1, 0(x2)` |
| `lh` | I | rd = SignExt(Mem[rs1+imm][15:0]) | `lh x1, 0(x2)` |
| `lw` | I | rd = SignExt(Mem[rs1+imm][31:0]) | `lw x1, 4(x2)` |
| `ld` | I | rd = Mem[rs1+imm][63:0] | `ld x1, 8(x2)` |
| `lbu` | I | rd = ZeroExt(Mem[rs1+imm][7:0]) | `lbu x1, 0(x2)` |
| `lhu` | I | rd = ZeroExt(Mem[rs1+imm][15:0]) | `lhu x1, 0(x2)` |
| `lwu` | I | rd = ZeroExt(Mem[rs1+imm][31:0]) | `lwu x1, 0(x2)` |
| `sb` | S | Mem[rs1+imm][7:0] = rs2[7:0] | `sb x1, 0(x2)` |
| `sh` | S | Mem[rs1+imm][15:0] = rs2[15:0] | `sh x1, 0(x2)` |
| `sw` | S | Mem[rs1+imm][31:0] = rs2[31:0] | `sw x1, 4(x2)` |
| `sd` | S | Mem[rs1+imm][63:0] = rs2[63:0] | `sd x1, 8(x2)` |

### 13.3 분기/점프 명령어

| 명령어 | 형식 | 동작 | 범위/예제 |
|--------|------|------|---------|
| `beq` | B | if(rs1==rs2) PC+=imm | `beq x1, x2, L` |
| `bne` | B | if(rs1!=rs2) PC+=imm | `bne x1, x2, L` |
| `blt` | B | if(rs1<rs2) PC+=imm (부호) | `blt x1, x2, L` |
| `bge` | B | if(rs1>=rs2) PC+=imm (부호) | `bge x1, x2, L` |
| `bltu` | B | if(rs1<rs2) PC+=imm (무부호) | `bltu x1, x2, L` |
| `bgeu` | B | if(rs1>=rs2) PC+=imm (무부호) | `bgeu x1, x2, L` |
| `jal` | J | rd=PC+4; PC=PC+imm | ±1MB, `jal ra, func` |
| `jalr` | I | rd=PC+4; PC=(rs1+imm)&~1 | 임의, `jalr x0, 0(ra)` |

### 13.4 상수/PC 명령어

| 명령어 | 형식 | 동작 | 예제 |
|--------|------|------|------|
| `lui` | U | rd = imm << 12 | `lui x1, 0x12345` |
| `auipc` | U | rd = PC + (imm << 12) | `auipc x1, 0x10` |

### 13.5 비교 명령어

| 명령어 | 형식 | 동작 | 예제 |
|--------|------|------|------|
| `slt` | R | rd = (rs1 < rs2) ? 1 : 0 (부호) | `slt x1, x2, x3` |
| `sltu` | R | rd = (rs1 < rs2) ? 1 : 0 (무부호) | `sltu x1, x2, x3` |
| `slti` | I | rd = (rs1 < imm) ? 1 : 0 (부호) | `slti x1, x2, 10` |
| `sltiu` | I | rd = (rs1 < imm) ? 1 : 0 (무부호) | `sltiu x1, x2, 10` |

### 13.6 의사 명령어 퀵 레퍼런스

| 의사 명령어 | 실제 명령어 | 설명 |
|------------|----------|------|
| `nop` | `addi x0,x0,0` | No operation |
| `li rd, C` | `lui`+`addi` / `addi x0,C` | Load immediate |
| `mv rd, rs` | `addi rd,rs,0` | Copy register |
| `not rd, rs` | `xori rd,rs,-1` | Bitwise NOT |
| `neg rd, rs` | `sub rd,x0,rs` | Negate |
| `seqz rd, rs` | `sltiu rd,rs,1` | Set if == 0 |
| `snez rd, rs` | `sltu rd,x0,rs` | Set if != 0 |
| `sltz rd, rs` | `slt rd,rs,x0` | Set if < 0 |
| `sgtz rd, rs` | `slt rd,x0,rs` | Set if > 0 |
| `beqz rs, L` | `beq rs,x0,L` | Branch if == 0 |
| `bnez rs, L` | `bne rs,x0,L` | Branch if != 0 |
| `blez rs, L` | `bge x0,rs,L` | Branch if <= 0 |
| `bgez rs, L` | `bge rs,x0,L` | Branch if >= 0 |
| `bltz rs, L` | `blt rs,x0,L` | Branch if < 0 |
| `bgtz rs, L` | `blt x0,rs,L` | Branch if > 0 |
| `bgt rs1,rs2,L` | `blt rs2,rs1,L` | Branch if > |
| `ble rs1,rs2,L` | `bge rs2,rs1,L` | Branch if <= |
| `j L` | `jal x0,L` | Jump (no link) |
| `call L` | `auipc ra,off[31:12]`+`jalr` | Call function |
| `ret` | `jalr x0,0(ra)` | Return |
| `la rd, sym` | `auipc`+`addi` | Load address |

## 14. 핵심 개념 요약

> [!summary] Chapter 2 핵심 정리
>
> **ISA 설계 원칙**: 단순성 > 규칙성 > 적절한 타협 > 자주 쓰이는 것을 빠르게
>
> **명령어 형식**: R/I/S/B/U/J — 모두 32비트 고정
> - R: 레지스터 연산, I: 즉치/로드, S: 스토어
> - B: 분기(±4KB), U: 상위 20비트, J: 점프(±1MB)
>
> **레지스터 규약**:
> - s0-s11: Callee saved (함수가 보존 책임)
> - t0-t6, a0-a7, ra: Caller saved (호출자가 저장 책임)
>
> **메모리**: Load/Store 전용, Base+Offset 어드레싱, Little-Endian
>
> **프로시저 호출**: 인자 a0-a7, 반환값 a0-a1, 반환 주소 ra

> [!warning] 자주 실수하는 부분
> 1. `lui`+`addi`에서 하위 12비트 ≥ 0x800이면 lui에 +1 필요
> 2. Non-leaf 함수에서 ra 저장 필수
> 3. B-type 오프셋은 바이트 단위, imm[0]=0 (항상 짝수)
> 4. `sw rs2, imm(rs1)` — rs2가 저장할 데이터, rs1이 기주소
