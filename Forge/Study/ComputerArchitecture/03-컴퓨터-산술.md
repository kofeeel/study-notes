## 1. 정수 표현 (Integer Representation)

### 1.1 부호-크기 표현 (Sign-Magnitude)

| 비트 | 의미 |
|------|------|
| MSB (최상위 비트) | 부호 (0 = 양수, 1 = 음수) |
| 나머지 비트 | 크기 (절댓값) |

**문제점:**
- 0이 두 개 존재: `+0` = `0000 0000`, `-0` = `1000 0000`
- 덧셈 회로가 복잡해짐 (부호 별도 처리)
- 현대 프로세서에서는 미사용

### 1.2 1의 보수 (One's Complement)

$$-x = \overline{x} \quad \text{(모든 비트를 반전)}$$

**예시 (8비트):**
- $+7$ = `0000 0111`
- $-7$ = `1111 1000`

**문제점:** 0이 두 개 (`0000 0000`, `1111 1111`), 덧셈 시 End-around carry 필요

### 1.3 2의 보수 (Two's Complement)

$$-x = \overline{x} + 1$$

**예시 (8비트):**
- $+7$ = `0000 0111`
- $-7$ = `1111 1001`

**범위 (n비트):**

$$-2^{n-1} \leq x \leq 2^{n-1} - 1$$

| 비트 수 | 최솟값 | 최댓값 |
|---------|--------|--------|
| 8비트   | $-128$ | $+127$ |
| 16비트  | $-32768$ | $+32767$ |
| 32비트  | $-2{,}147{,}483{,}648$ | $+2{,}147{,}483{,}647$ |

> [!note] 2의 보수의 핵심 특성
> - 0이 오직 하나 (`0000 0000`)
> - 덧셈/뺄셈을 동일 회로로 처리 가능
> - $-2^{n-1}$ 은 2의 보수가 자기 자신 (대칭 없음)

**부호 확장 (Sign Extension):**  
MSB를 왼쪽으로 복사한다.

```
8비트  -3 = 1111 1101
16비트 -3 = 1111 1111 1111 1101
```

## 2. 2의 보수 산술

### 2.1 덧셈 (Addition)

일반 이진 덧셈과 동일하게 수행하고 캐리아웃(carry-out)은 버린다.

```
  0111 (+7)
+ 0001 (+1)
──────────
  1000 (-8)  ← 오버플로우 발생!
```

### 2.2 뺄셈 (Subtraction)

$$A - B = A + (-B) = A + (\overline{B} + 1)$$

피감수의 2의 보수를 구해 덧셈으로 변환한다.

### 2.3 오버플로우 감지 (Overflow Detection)

> [!warning] 오버플로우 조건표
>
> | 피연산자 A 부호 | 피연산자 B 부호 | 결과 부호 | 오버플로우? |
> |:--------------:|:--------------:|:---------:|:-----------:|
> | 양수 (+)        | 양수 (+)        | 음수 (-)  | **YES** |
> | 음수 (-)        | 음수 (-)        | 양수 (+)  | **YES** |
> | 양수 (+)        | 음수 (-)        | 무관      | NO |
> | 음수 (-)        | 양수 (+)        | 무관      | NO |

**하드웨어 감지 방법:**

$$\text{Overflow} = C_{n-1} \oplus C_n$$

$C_{n-1}$: MSB로의 캐리인, $C_n$: MSB에서의 캐리아웃

> [!tip] 부호 없는 정수(Unsigned)와 오버플로우
> 부호 없는 정수에서는 캐리아웃($C_n$)이 1이면 오버플로우.  
> RISC-V에서는 `add` vs `addu` 구분 없이 모두 같은 명령어를 사용하고, 소프트웨어가 처리함.

## 3. 곱셈 (Multiplication)

### 3.1 순차 곱셈기 (Sequential Multiplier)

**알고리즘 개요:**

```
Product = 0
for i = 0 to 31:
    if Multiplier[0] == 1:
        Product = Product + Multiplicand
    Multiplicand <<= 1   (왼쪽 시프트)
    Multiplier  >>= 1   (오른쪽 시프트)
```

**최적화된 버전:**

```
{HI | LO} = {Product(64bit)}
for i = 0 to 31:
    if LO[0] == 1:
        HI = HI + Multiplicand
    {HI | LO} >>= 1  (부호 확장 시프트)
```

- 32 × 32비트 = 64비트 결과
- RISC-V: `mul` (하위 32비트), `mulh` (상위 32비트)

### 3.2 Booth's Algorithm (개념)

연속된 1비트를 묶어 덧셈 횟수를 줄이는 알고리즘.

**핵심 아이디어:** $0111 = 1000 - 0001$

| 현재 비트 | 이전 비트 | 동작 |
|:---------:|:---------:|------|
| 0 | 0 | 아무것도 안 함 (shift only) |
| 1 | 0 | Partial product에 Multiplicand **빼기** |
| 0 | 1 | Partial product에 Multiplicand **더하기** |
| 1 | 1 | 아무것도 안 함 (shift only) |

> [!note] Booth's Algorithm의 장점
> - 음수 × 음수, 음수 × 양수 자동 처리
> - 연속 1 구간에서 연산 횟수 감소
> - 현대 곱셈기 설계의 기초

## 4. 나눗셈 (Division)

### 4.1 복원 나눗셈 (Restoring Division)

```
Remainder = Dividend
for i = 0 to 31:
    Remainder = 2 * Remainder - Divisor
    if Remainder >= 0:
        Quotient[i] = 1
    else:
        Quotient[i] = 0
        Remainder = Remainder + Divisor  ← 복원(Restore)
```

**예시: 7 ÷ 2**

```
초기: Remainder=0111, Divisor=0010
Step1: R=0111<<1 - 0010 = 1110-0010 = 1100 → 음수 → Q[31]=0, R복원=1110/2=0111
...
결과: Quotient=3, Remainder=1
```

> [!warning] 나눗셈 예외
> - **0으로 나누기**: 하드웨어가 감지 불가 → 소프트웨어(OS) 처리
> - 오버플로우: $-2^{31} \div -1$ 결과가 32비트 범위 초과

## 5. IEEE 754 부동소수점 (Floating-Point)

### 5.1 표현 형식

$$\text{Value} = (-1)^S \times M \times 2^E$$

- $S$: 부호 비트 (Sign)
- $M$: 가수 (Mantissa / Significand)  
- $E$: 지수 (Exponent)

#### 단정밀도 (Single Precision, 32비트)

```
 31  30      23  22                    0
┌───┬──────────┬──────────────────────┐
│ S │ Exponent │      Fraction        │
│ 1 │   8 bit  │       23 bit         │
└───┴──────────┴──────────────────────┘
```

| 필드 | 비트 수 | 범위 / 의미 |
|------|--------|-------------|
| Sign (S) | 1 | 0=양수, 1=음수 |
| Exponent | 8 | 저장값 = 실제 지수 + **127** (bias) |
| Fraction | 23 | 소수점 아래 (정규화 시 앞에 1 암묵적) |

**Bias = 127** (= $2^{8-1} - 1$)

#### 배정밀도 (Double Precision, 64비트)

```
 63  62          52  51                                    0
┌───┬──────────────┬────────────────────────────────────────┐
│ S │   Exponent   │              Fraction                  │
│ 1 │    11 bit    │               52 bit                   │
└───┴──────────────┴────────────────────────────────────────┘
```

**Bias = 1023** (= $2^{11-1} - 1$)

### 5.2 정규화 (Normalization)

정규화된 수: $1.fraction \times 2^{exp}$ 형태

- 정수부의 1은 **암묵적(hidden bit)** — 저장하지 않음
- 따라서 단정밀도는 사실상 **24비트** 유효 숫자

**예시:** $-0.75_{10}$ 를 단정밀도로 변환

```
0.75 = 0.11₂ = 1.1₂ × 2⁻¹

S = 1
Exponent = -1 + 127 = 126 = 0111 1110₂
Fraction = 1000 0000 0000 0000 0000 000₂ (소수점 아래 부분)

결과: 1 01111110 10000000000000000000000
```

### 5.3 특수값 (Special Values)

| 지수 (저장값) | 가수 (Fraction) | 의미 |
|:------------:|:---------------:|------|
| `0000 0000` (0) | 0 | $\pm 0$ (Zero) |
| `0000 0000` (0) | $\neq$ 0 | 비정규화수 (Denormalized / Subnormal) |
| `1111 1111` (255) | 0 | $\pm\infty$ (Infinity) |
| `1111 1111` (255) | $\neq$ 0 | NaN (Not a Number) |
| 나머지 (1~254) | 임의 | 정규화수 (Normalized) |

> [!note] 비정규화수 (Denormalized Number)
> - 지수 = 0, 가수 ≠ 0 일 때
> - 암묵적 1 비트 없음: $0.fraction \times 2^{-126}$
> - $0$에 가까운 매우 작은 수 표현 가능
> - Gradual underflow 지원

### 5.4 지수 범위

**단정밀도:**
- 저장 지수 범위: 1 ~ 254 (0과 255는 특수값)
- 실제 지수 범위: $-126 \leq E \leq +127$
- 최댓값: $\approx 3.4 \times 10^{38}$
- 최솟값 (정규화): $\approx 1.2 \times 10^{-38}$
- 십진 유효 자릿수: $\approx 7$자리

**배정밀도:**
- 실제 지수 범위: $-1022 \leq E \leq +1023$
- 최댓값: $\approx 1.8 \times 10^{308}$
- 십진 유효 자릿수: $\approx 15$자리

### 5.5 부동소수점 덧셈 과정

**단계:**
1. **지수 맞춤**: 작은 지수를 큰 지수에 맞게 가수를 오른쪽 시프트
2. **가수 덧셈**: 정렬된 가수끼리 더하기
3. **정규화**: 결과를 $1.xxx \times 2^e$ 형태로 변환
4. **반올림**: 하위 비트 처리
5. **오버플로우/언더플로우 검사**

**예시: $0.5 + -0.4375$ (단정밀도)**

```
0.5      = 1.000 × 2⁻¹
-0.4375  = -1.110 × 2⁻²

Step1: 지수 맞춤
  0.5    = 1.000 × 2⁻¹
 -0.4375 = -0.111 × 2⁻¹  (오른쪽 1비트 시프트)

Step2: 덧셈
  1.000
- 0.111
──────
  0.001 × 2⁻¹

Step3: 정규화
  0.001 × 2⁻¹ = 1.000 × 2⁻⁴

결과: 1.000 × 2⁻⁴ = 0.0625
```

### 5.6 부동소수점 곱셈 과정

1. **부호**: XOR로 결과 부호 결정
2. **지수 덧셈**: $E_{result} = E_1 + E_2 - \text{bias}$ (bias 한 번 빼기)
3. **가수 곱셈**: 가수끼리 곱하기
4. **정규화 + 반올림**
5. **오버플로우/언더플로우 검사**

### 5.7 반올림 모드 (Rounding Modes)

IEEE 754는 4가지 반올림 모드 정의:

| 모드 | 설명 | 예시 (+2.5 → 정수) |
|------|------|-------------------|
| **RNE** (Round to Nearest Even) | 최근접값, 동률 시 짝수 | 2 (2는 짝수) |
| **RTZ** (Round Toward Zero) | 절댓값 감소 방향 | 2 |
| **RUP** (Round Up, +∞ 방향) | 양의 무한대 방향 | 3 |
| **RDN** (Round Down, -∞ 방향) | 음의 무한대 방향 | 2 |

> [!tip] RNE (Banker's Rounding)
> 기본 반올림 모드. 0.5에서 짝수 방향으로 반올림하여 통계적 편향을 줄임.
> - `2.5 → 2` (2는 짝수)
> - `3.5 → 4` (4는 짝수)

**Guard / Round / Sticky 비트:**
- **Guard bit**: 최하위 비트 바로 아래
- **Round bit**: Guard 아래
- **Sticky bit**: Round 아래 모든 비트의 OR

이 3비트를 이용해 정확한 반올림 결정.

## 6. 부동소수점 정밀도 한계와 오차

### 6.1 표현 불가능한 수

이진 부동소수점으로 정확히 표현할 수 없는 십진수가 존재:

$$0.1_{10} = 0.000110011001100..._2 \quad \text{(무한 반복)}$$

$$0.1 + 0.2 = 0.30000000000000004... \neq 0.3$$

### 6.2 오차 종류

| 오차 유형 | 발생 원인 | 예시 |
|-----------|-----------|------|
| **표현 오차** (Representation Error) | 이진수로 정확히 표현 불가 | $0.1$, $0.3$ |
| **반올림 오차** (Rounding Error) | 유효 비트 이하 버림 | 연속 덧셈 누적 |
| **흡수 오차** (Absorption) | 큰 수 + 작은 수 | $10^{15} + 1 = 10^{15}$ |
| **소거 오차** (Catastrophic Cancellation) | 비슷한 두 수의 뺄셈 | $1.0000001 - 1.0000000$ |

### 6.3 부동소수점 비교 주의

```c
// 잘못된 비교
if (a + b == c) { ... }

// 올바른 비교
if (fabs(a + b - c) < epsilon) { ... }
```

## 7. 면접 빈출 질문 + 모범 답변

> [!question] Q1. 2의 보수를 사용하는 이유는?
> **A:** 2의 보수는 세 가지 핵심 장점이 있습니다.
> 1. **0이 유일**: 부호-크기나 1의 보수와 달리 $+0$, $-0$ 문제가 없습니다.
> 2. **하드웨어 단순화**: 덧셈과 뺄셈을 동일한 회로로 처리할 수 있어 ALU 설계가 단순해집니다.
> 3. **자연스러운 오버플로우 처리**: 최상위 캐리만 버리면 결과가 자동으로 올바른 2의 보수 값이 됩니다.

---

> [!question] Q2. `0.1 + 0.2 ≠ 0.3`인 이유는?
> **A:** IEEE 754 부동소수점은 이진수로 표현되는데, $0.1$과 $0.2$는 이진수로 무한 소수입니다.
> $$0.1_{10} = 0.\overline{0011}_2$$
> 유한한 비트(단정밀도 23비트)로 잘라서 저장하면 미세한 표현 오차가 발생합니다. 두 오차가 더해지면 $0.30000000000000004...$가 됩니다. 해결책은 `epsilon` 비교나 `BigDecimal` 같은 십진 산술 라이브러리 사용입니다.

---

> [!question] Q3. 오버플로우(Overflow)와 캐리(Carry)의 차이는?
> **A:**
> - **Carry**: 최상위 비트에서 발생하는 올림수. 부호 없는 정수에서 오버플로우 의미.
> - **Overflow**: **부호 있는 정수 연산에서** 결과가 표현 범위를 벗어나는 것.
>
> 2의 보수에서 오버플로우 판정: $C_{n-1} \oplus C_n = 1$ (MSB로의 캐리인과 캐리아웃이 다를 때)
>
> 예: `0111 + 0001 = 1000` → 캐리 없음, 오버플로우 있음 (+127 + 1 = -128)

---

> [!question] Q4. NaN(Not a Number)이란 무엇이고 언제 발생하나요?
> **A:** NaN은 IEEE 754에서 정의되지 않거나 불가능한 연산 결과를 나타내는 특수값입니다.
>
> **발생 조건:**
> - $0 \div 0$
> - $\sqrt{-1}$ (실수 범위)
> - $\infty - \infty$
> - $\infty \times 0$
>
> **NaN의 특성:** `NaN != NaN` (자기 자신과도 같지 않음). 따라서 NaN 검사는 `isnan()` 함수를 사용해야 합니다.

---

> [!question] Q5. 부동소수점에서 비정규화수(Denormalized Number)가 필요한 이유는?
> **A:** 정규화수의 최솟값(단정밀도: $\approx 1.2 \times 10^{-38}$) 이하의 수를 표현하기 위해서입니다.
>
> 비정규화수 없이는 정규화 최솟값 미만에서 갑자기 0으로 떨어지는 **abrupt underflow**가 발생합니다. 비정규화수를 사용하면 0에 가까울수록 점점 정밀도를 희생하며 표현하는 **gradual underflow**가 가능해져 더 안정적인 수치 계산이 가능합니다.

---

> [!question] Q6. IEEE 754의 bias(편향) 지수 표현을 쓰는 이유는?
> **A:** 부동소수점 수의 **크기 비교를 정수 비교처럼 수행**하기 위해서입니다.
>
> Bias 표현을 쓰면 지수 필드가 항상 양수(0부터 시작)가 되어, 부동소수점 수를 정수 비교 명령어로 정렬/비교할 수 있습니다. 예를 들어 지수 -126을 저장값 1로, +127을 저장값 254로 표현하면 저장값이 클수록 수도 큰 관계가 유지됩니다.

---

> [!question] Q7. 단정밀도(float)와 배정밀도(double)의 차이와 선택 기준은?
> **A:**
>
> | 항목 | float (32비트) | double (64비트) |
> |------|---------------|----------------|
> | 지수 비트 | 8 | 11 |
> | 가수 비트 | 23 (+1 hidden) | 52 (+1 hidden) |
> | 십진 정밀도 | ~7자리 | ~15자리 |
> | 범위 | $\pm 3.4 \times 10^{38}$ | $\pm 1.8 \times 10^{308}$ |
> | 메모리 | 4바이트 | 8바이트 |
>
> **선택 기준:**
> - 과학 계산, 금융 → double
> - GPU, 게임 그래픽, 머신러닝 추론 → float (메모리/속도 우선)
> - 최고 정밀도 필요 → `long double` 또는 소프트웨어 십진 산술

---

> [!question] Q8. Booth's Algorithm의 핵심 아이디어는?
> **A:** 연속된 1 비트를 덧셈 한 번과 뺄셈 한 번으로 대체하여 연산 횟수를 줄입니다.
>
> 예: `0111` (= 7)을 곱할 때 3번 더하는 대신, `1000 - 0001`로 변환해 한 번 더하고 한 번 빼면 됩니다.
>
> 각 비트 전환 지점(0→1, 1→0)에서만 연산이 발생하므로, 피승수가 큰 연속 1 블록을 가질수록 효율적입니다. 또한 2의 보수 음수 곱셈도 자연스럽게 처리됩니다.

---

> [!question] Q9. 부동소수점 연산은 결합법칙이 성립하나요?
> **A:** **성립하지 않습니다.** 이는 부동소수점의 반올림 오차 때문입니다.
>
> ```python
> a = 1e30
> b = -1e30
> c = 1.0
> (a + b) + c = 0.0 + 1.0 = 1.0   # 올바름
> a + (b + c) = 1e30 + (-1e30 + 1) ≈ 1e30 + (-1e30) = 0.0  # 흡수 오차!
> ```
>
> 따라서 수치 계산에서 연산 순서가 결과에 영향을 미칩니다. Kahan Summation Algorithm 등을 써서 누적 오차를 줄일 수 있습니다.

---

> [!question] Q10. 정수 오버플로우를 감지하는 방법은?
> **A:** 언어/플랫폼별 접근이 다릅니다.
>
> **하드웨어 수준:**
> - RISC-V: `add` 명령어에서 $C_{n-1} \oplus C_n$ 이 1이면 Overflow 트랩
>
> **소프트웨어 수준 (C):**
> ```c
> // 덧셈 오버플로우 검사
> int safe_add(int a, int b, int *result) {
>     if ((b > 0 && a > INT_MAX - b) ||
>         (b < 0 && a < INT_MIN - b)) {
>         return -1; // overflow
>     }
>     *result = a + b;
>     return 0;
> }
> ```
>
> **C++20:** `std::overflow_wrapper`  
> **Rust:** 기본이 오버플로우 패닉, `wrapping_add()` / `saturating_add()`로 명시적 제어

---

> [!question] Q11. `int` 최솟값에 `-1`을 곱하면 어떻게 되나요?
> **A:** 정의되지 않은 동작(Undefined Behavior, UB)이 됩니다 (C/C++ 기준).
>
> $-2^{31}$의 절댓값은 $2^{31}$인데, 이는 `int` 최댓값 $2^{31} - 1$을 초과합니다. 2의 보수에서 $-(-2^{31}) = -2^{31}$ (자기 자신)이 되는 현상이 하드웨어 수준에서 발생하지만, C 표준은 이를 UB로 규정하여 컴파일러가 임의로 최적화할 수 있습니다.

### 문제 2. 2의 보수 덧셈과 오버플로우 판별

**Q:** 8비트 부호 있는 정수로 $100 + 50$ 을 계산하고, 오버플로우 여부를 판별하라.

<details>
<summary>풀이 보기</summary>

$100_{10} = 0110\ 0100_2$  
$50_{10}  = 0011\ 0010_2$

```
  0110 0100
+ 0011 0010
───────────
  1001 0110
```

**결과:** `1001 0110` = $-128 + 16 + 4 + 2 = -106$

**오버플로우 판별:**  
- 두 피연산자 모두 양수 (MSB = 0)
- 결과가 음수 (MSB = 1)
- → **오버플로우 발생!**

$C_{n-1} = 1$ (7번째 비트로의 캐리), $C_n = 0$ (MSB에서 캐리아웃 없음)  
$C_{n-1} \oplus C_n = 1 \oplus 0 = 1$ → 오버플로우 확인

**정답:** 계산 결과는 `1001 0110`이나 오버플로우 발생. 실제 값 150은 8비트 범위(-128~127)를 초과.

</details>

<details>

정수부: $13 = 1101_2$

- $E_{stored} = 3 + 127 = 130 = 1000\ 0010_2$
- Fraction = `10101 000...0` (23비트, 암묵적 1 제외)

**Step 4:** 조합

```
S    Exponent       Fraction
1  10000010  10101000000000000000000
```

**16진수:** `C1540000`

**검증:**  
$(-1)^1 \times 1.10101_2 \times 2^{130-127} = -1.10101_2 \times 2^3 = -1101.01_2 = -13.25$ ✓

</details>

### 문제 6. 오버플로우 판별 (뺄셈)

### 문제 7. 비정규화수 판별

**Q:** `0 00000000 00000000000000000000001` (32비트)는 어떤 값인가?

<details>
<summary>풀이 보기</summary>

**필드 분석:**
- $S = 0$ (양수)
- $E_{stored} = 0000\ 0000 = 0$ → **비정규화수 (Denormalized)**
- Fraction = `00000000000000000000001`

**비정규화수 공식:**  
$$\text{Value} = (-1)^S \times 0.fraction_2 \times 2^{-126}$$

Fraction = $2^{-23}$ (최하위 비트만 1)

$$\text{Value} = +2^{-23} \times 2^{-126} = 2^{-149}$$

**정답:** 단정밀도에서 표현 가능한 **최솟값** $= 2^{-149} \approx 1.4 \times 10^{-45}$

</details>

### 문제 8. Booth's Algorithm 적용

**Q:** Booth's Algorithm으로 $3 \times (-2)$ (4비트)를 계산하라.

<details>
<summary>풀이 보기</summary>

$3 = 0011_2$, $-2 = 1110_2$

**Multiplicand** = $3 = 0011$  
**Multiplier** = $-2 = 1110$, 이전 비트 $Q_{-1} = 0$

| 단계 | 현재 $Q_0$ | $Q_{-1}$ | 동작 | Accumulator | Multiplier | $Q_{-1}$ |
|------|:----------:|:--------:|------|:-----------:|:----------:|:--------:|
| 초기 | — | 0 | — | `0000` | `1110` | `0` |
| 1 | 0 | 0 | 시프트 | `0000` | `0111` | `0` |
| 2 | 1 | 0 | A -= M (A += $\overline{M}+1$) | `1101` → 시프트 | `1110` | `1` |

> 축약 풀이: $3 \times (-2) = -6 = 1111\ 1010_2$ (8비트 2의 보수)  
> 4비트 결과: `1010` = $-6$ ✓

</details>

### 문제 10. 정밀도 손실 분석

**Q:** 단정밀도 부동소수점에서 $16{,}777{,}216 + 1$ 의 결과는?

<details>
<summary>풀이 보기</summary>

$16{,}777{,}216 = 2^{24}$

단정밀도의 유효 가수 비트는 **23비트** (+ hidden bit 1 = 24비트).

$2^{24} = 1.000...0_2 \times 2^{24}$ (가수 모두 0, 24비트 정밀도 소진)

$1$을 더하려면 $2^{24}$의 위치에 $2^0$ 더하기:  
최하위 표현 가능 단위 = $2^{24} \times 2^{-23} = 2^1 = 2$

따라서 $1 < 2$ 이므로 **흡수(absorption)** 발생:

$$16{,}777{,}216 + 1 = 16{,}777{,}216$$

**이것이 `float` 타입의 한계!** $2^{24}$ 이상에서는 연속 정수를 표현할 수 없음.

</details>

## 9. 핵심 공식/변환 요약표

### 정수 표현

| 방식 | 양수 변환 | 음수 변환 | 0 표현 |
|------|-----------|-----------|--------|
| 부호-크기 | 그대로 | MSB = 1 | 두 개 |
| 1의 보수 | 그대로 | 전체 반전 | 두 개 |
| 2의 보수 | 그대로 | 전체 반전 + 1 | 하나 |

### 2의 보수 공식

$$-x = \overline{x} + 1$$

$$\text{범위: } -2^{n-1} \leq x \leq 2^{n-1}-1$$

$$\text{Overflow} = C_{n-1} \oplus C_n$$

### IEEE 754 요약

| 항목 | 단정밀도 (32비트) | 배정밀도 (64비트) |
|------|:----------------:|:----------------:|
| 부호 비트 | 1 | 1 |
| 지수 비트 | 8 | 11 |
| 가수 비트 | 23 | 52 |
| Bias | 127 | 1023 |
| 지수 범위 | $-126$ ~ $+127$ | $-1022$ ~ $+1023$ |
| 십진 정밀도 | ~7자리 | ~15자리 |
| 최대 양수 | $\approx 3.4 \times 10^{38}$ | $\approx 1.8 \times 10^{308}$ |

### IEEE 754 특수값 (단정밀도 기준)

| 지수 저장값 | 가수 | 값 |
|:-----------:|:----:|:--:|
| 0 (`0x00`) | 0 | $\pm 0$ |
| 0 (`0x00`) | $\neq 0$ | Denormalized |
| 1–254 | 임의 | Normalized |
| 255 (`0xFF`) | 0 | $\pm \infty$ |
| 255 (`0xFF`) | $\neq 0$ | NaN |

### 지수 변환

$$E_{actual} = E_{stored} - \text{bias}$$

$$E_{stored} = E_{actual} + \text{bias}$$

### 부동소수점 덧셈 단계

```
1. 지수 정렬 (작은 쪽 가수 오른쪽 시프트)
2. 가수 덧셈/뺄셈
3. 정규화 (1.xxx × 2^e 형태로)
4. 반올림 (Guard/Round/Sticky 비트)
5. 오버플로우/언더플로우 검사
```

### 자주 쓰는 이진 변환

| 십진 소수 | 이진 소수 |
|:---------:|:---------:|
| 0.5 | $0.1_2$ |
| 0.25 | $0.01_2$ |
| 0.125 | $0.001_2$ |
| 0.75 | $0.11_2$ |
| 0.375 | $0.011_2$ |
| 0.1 | $0.0\overline{0011}_2$ (무한반복) |
| 0.3 | $0.0\overline{1001}_2$ (무한반복) |

---

> [!summary] 핵심 요약
> 1. **2의 보수**: 현대 CPU의 표준. 0 하나, 회로 단순, $-x = \overline{x}+1$
> 2. **오버플로우**: 같은 부호 두 수를 더해 다른 부호 나오면 발생
> 3. **IEEE 754**: $(-1)^S \times 1.fraction \times 2^{E-bias}$. 단정밀도 bias=127, 배정밀도 bias=1023
> 4. **0.1 + 0.2 ≠ 0.3**: 이진수로 0.1, 0.3은 무한 소수 → 표현 오차
> 5. **NaN != NaN**: 유일한 자기 자신과 다른 값 → `isnan()` 사용
> 6. **$2^{24}$ 이상 float**: 연속 정수 표현 불가 (정밀도 한계)
