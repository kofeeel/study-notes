## 학습법 (오니짱용)

1. **문서 1개 = 한 시스템.** 한 번에 7개 쏟지 말고 하나씩 손에 붙이고 다음으로.
2. **옆에 실제 소스 열어두고 줄 번호 대조.** 문서만 읽으면 "안다고 착각"하기 쉬움. 코드를 직접 봐야 붙음.
3. **§마지막 "직접 설명 연습" = 보지 말고 소리내어.** 막히는 항목이 진짜 안 아는 부분. 거기를 다시.
4. **면접 Q&A는 답을 외우지 말고 "왜"를 이해.** 질문이 변형돼도 답할 수 있어야.

## 가장 중요한 3개 (시간 없으면 이것만)

1. **동기 사망** (03 §5) — `SetNumericAttributeBase`가 변화 델리게이트를 *같은 콜스택*에서 동기 발화. 대부분 지원자가 모름 = 차별점.
2. **패링 게이팅** (01 §3) — 패링 감지 코드는 IncomingDamage가 들어와야 돈다. "패링 안 됨" = 보통 "히트 안 박힘".
3. **데이터드리븐 × 비대칭** (01 §4, 02 §3, 03 §7) — if 분기 대신 CDO/DataAsset로 진영·적종 차이를 표현. 확장에 열린 설계.
