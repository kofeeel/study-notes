# ProjectKD — 내가 설계·구현한 전투/적 AI 시스템

> **목표 포지션** — 테크니컬 전투 디자이너 (몬스터 전투 액션 설계 + C++/UE5 끝까지 구현).
> 이 문서는 "내가 무엇을 만들었나"를, 케이스마다 **설계 의도 → 구현 → 카운터플레이 → 이터레이션**으로 정리한다.
> 디버깅·근본원인 추적 사례는 → [[ProjectKD-문제해결-사례집]].

**엔진/스택** — UE5.6 · GAS(Ability/Tags/Tasks) · C++ 중심(헤더 설계 + 구현), 데이터드리븐(DataAsset)
**담당 도메인** — 타격판정, 적 AI, GAS 코어, 사망/처형 사이클, 히트 피드백, 전투 아키텍처
**역할 한 줄** — "내가 설계한 몬스터를 C++/UE5로 끝까지 굴러가게 만드는 사람"

## 1. WeaponTrace 타격판정 + 패링 게이팅 — 플래그십

> 상세 케이스스터디: [[ProjectKD-문제해결-사례집#1-엘리트-도끼-패링이-간헐적]] / 설계명세 [[ProjectKD-패링-기능명세서]]

### 설계 의도
무기 소켓을 따라 캡슐을 sweep해 "실제 칼날이 닿은 순간"에만 히트를 박는다. 모든 전투 피드백(데미지·패링·히트스탑)이 이 한 판정에서 갈라진다.

### 핵심 통찰 — 패링은 트레이스 히트에 100% 게이팅된다
```
적 트레이스가 플레이어를 맞춤 → 데미지 GE 적용 → AS_Combat가 패링 게이트 발화
트레이스 안 맞음 → 데미지 GE 없음 → 패링 게이트 호출조차 안 됨
```
→ "패링이 안 된다"의 90%는 패링 로직이 아니라 **상류 트레이스 문제**. 디버깅 1순위가 GE가 아니라 "히트가 실제로/언제 박혔나"라는 것을 데이터 흐름으로 규명.

### 구현 — 윈도우별 트레이스 오버라이드 (확장에 열린 설계)
트레이스 파라미터(소켓/반지름/모드)를 GA 전역이 아니라 **`ANS_WeaponTrace`(AnimNotifyState) 윈도우 단위**로 내림. 한 몽타주가 윈도우마다 다른 트레이스 모양을 그린다.
- 찍기 윈도우: 도끼 **머리 소켓** 시작 → 히트 시점 = 머리 도달 = 시각 일치 → 패링 가능
- 스윕 윈도우: 비움 → GA 디폴트(자루 전체)
- 전달은 게임플레이 이벤트 페이로드(`OptionalObject`)로 동기 디스패치, 미설정 시 GA 디폴트로 graceful fallback
- 같은 메커니즘이 플레이어 공중공격·보스·(향후)맨몸격투까지 재사용됨

### 카운터플레이 설계 원칙 — 히트 정확도 ⊥ 패링 관대함
한 레버(적 무기 캡슐 크기)가 두 가지를 동시에 조종하던 결합을 끊었다.

| 원하는 것 | 맞는 레버 |
|---|---|
| 적 안 맞추기 쉽게(회피 가능) | 전조 길이/가독성, 공격 속도·추적 |
| 전투 긴장감 | 데미지·포이즈·빈도, 노랑(언블록) 섞기 |
| **패링 난이도** | **플레이어 퍼펙트 윈도우 길이**(적 히트박스 아님) |

적 히트는 정확하게(머리 소켓+타이트 윈도우), 패링 관대함은 플레이어 쪽에서. 세키로/스텔라 블레이드 모델 — 적 히트박스는 정직하고, 디플렉트 *윈도우*가 관대함 레버.

### 진영별 비대칭 = 분기가 아니라 데이터
- 플레이어: 1 GA 활성화 = 1스윙 → "1스윙 1히트"(`bOncePerActor=true`)
- 적: 1 GA 활성화 = 몽타주(다단 스윙) → "스윙(윈도우)당 1히트"(`bOncePerActor=false`)
- `if` 분기가 아니라 **per-faction CDO 디폴트(생성자)**로 표현. (진영별 중간 base 분리: `GA_PlayerAttackBase` / `GA_EnemyWeaponTraceBase`)

## 2. 적 AI 포지셔닝 — 토큰 / EQS / Crowd 직교 모델

> 상세: 위키 [[ai-eqs-crowd-eqs]] · 거리밴드 함정 → [[ProjectKD-문제해결-사례집#3-적이-안-쏘고-따라옴]]

### 설계 의도
적의 "어디 설지/어떻게 접근할지"를 god-tree(거대 분기 트리) 없이, **서로 안 겹치는 3축**으로 분리한다. 한 축을 바꿔도 나머지에 영향 없음.

```
토큰(EncounterSubsystem) = "누가 칠지"   동시 공격자 ≤2, hold-time 2.5s 로테이션
EQS                      = "어디 설지/접근할지"
MoveTo + Detour Crowd    = "그 목적지까지 경로 + 국소 회피"
```

### 구현
- **공유 BT 골격 1개 + 데이터드리븐 공격선택** — 적별 BT를 따로 안 만든다. 거리밴드 + 쿨다운 + 가중 랜덤으로 `SelectAttack`이 공격을 고르고, 다양성은 GA 세트 + 적 정의 DataAsset에서 나온다. BT는 무분기.
- **EQS 표준형** — Donut 제너레이터(중심=플레이어), 빌트인 테스트(Distance→Trace→Pathfinding)로 커스텀 Test 0개. melee 포위는 360° 도넛 + Score Only 트레이스(보이는 자리 *선호*, 안 보이면 *금지* 아님).
- **원거리 면제** — 토큰(동시공격 제한)은 근접 전용 자원. 원거리 kiter는 토큰 강제 부여 + reposition 차단(안 그러면 토큰 못 받은 활이 chase로 빠져 플레이어한테 비빔).

### 카운터플레이 설계
근접 적 + 원거리 적을 섞으면 플레이어가 "어디에 설지"를 고민하게 된다. 난이도를 적 *수*가 아니라 *조합*으로 만드는 인카운터 설계.

### 이터레이션
- LOS 라인트레이스로 시작 → PIE에서 "적이 바보처럼 보일 때"(직선 정면 접근/로봇 같은 kiting/코너 자가감금)를 트리거로 EQS 에스컬레이션. YAGNI를 과적용하지 않고 학습목표(포지셔닝 AI)에 투자.
- `facing 뒷걸음 버그`: 멀어져 patrol 복귀 시에도 플레이어 보며 뒷걸음 → `UpdateCombatFacing` 교전거리 게이트로 해소(상세 사례집 #5).

## 3. 원거리 적 조준·궤적 (활)

> 위키 [[ranged-enemy-projectile-aiming]] · 살아있는 kiting 설계 [[archer-locomotion-design]]

### 설계 의도
활잡이는 "거리를 강제하는" 적. 멀리서 직사로 쏘고, 다가가면 거리를 벌린다 → 플레이어가 풍보(거리 좁히기)를 배우게 만든다.

### 구현 핵심
- **조준 = muzzle→타겟 방향** (actor forward 금지). 컨트롤러 SetFocus는 yaw(수평)만 추적해서 점프/공중 플레이어를 못 맞춤 → spawn rotation = `(TargetLoc - MuzzleLoc).Rotation()`.
- **직선 유지** (`ProjectileGravityScale=0`). 빠른 직사 = 회피/패링 타이밍 게임. 포물선은 차지샷 "착탄 예고형" 카드로만 보류(베지에 유도탄 아님 — 물리 중력).
- **살아있는 kiting 3밴드** — 사격 / 뒷걸음(StrafeWalk) / 백스텝(Dodge). facing 분리 + 2D BlendSpace + 상체 사격 슬롯.
- **평상시 자세 게이트** — `bHasTarget`(블랙보드 TargetActor 유무)으로 상체 aim 슬롯 on/off. 인지 전엔 활 내린 patrol 자세, 인지 즉시 활 듦.

## 4. 사망 · 랙돌 · 처형 · 데스블로 사이클

> 상세 전문: 위키/메모리 [[ragdoll-death-montage-decision]] · 처형 메커닉 [[execution-mechanic]]

### 설계 의도
"경직 중 강공 피격" = 처형. 적이 죽을 수도(Health≤0 랙돌), 살아서 데스블로 후 일어날 수도 있는 **반응형** 메커닉. 플레이어는 처형을 *트리거*만 하고 판정·연출은 전부 적 측이 소유한다(도메인 분리).

### 구현
- **사망 = 완전 동기** — `SetNumericAttributeBase(Health)` → 변화 델리게이트 동기 발화 → `HandleDeath`가 GE 적용 콜스택 *안에서* 전부 실행. (진단 로그 `bExecutionDeath=1`로 증명. 한때 "지연 사망" 가설을 세웠으나 오진으로 확인하고 폐기.)
- **랙돌 하이브리드** — DeathMontage 지정 시 몽타주→랙돌, 미지정 시 즉시 랙돌, 처형 사망은 피니셔가 곧 죽음 연출이라 몽타주 스킵하고 바로 랙돌.
- **데스블로** — `bSurvivable`/`DeathblowHealthThreshold`/`DeathblowMontage`로 데이터 분기. 잡몹은 항상 데스블로(즉사), 엘리트는 생존 후 데스블로 모션 → 기상.
- **단일 판정 창구** — `ExecutionComponent::IsExecutionDeath()`가 죽음몽타주 스킵을 단일 판단. `EnterRagdoll()` 멱등 헬퍼(3경로 공용) + 백스톱 타이머.

### 이터레이션 (값진 실패 → 정답)
랙돌 대신 `bPauseAnims`(프레임 동결)/몽타주 끝프레임 유지로 "비물리 사망"을 시도했다가 **"처형 후 공중에서 멈춤"** 버그 → 물리가 없으니 공중 프레임이 박제됨. 전부 되돌리고 랙돌로 회귀. 핵심 교훈: 꺾임의 진범은 코드가 아니라 **PhysicsAsset**이었음(교체로 해결). (사례집 #2)

## 5. 히트 피드백 + 비대칭 경직 모델

> [[hit-feedback-decoupled-from-ge]] · [[combat-model-asymmetric-stagger]] · [[hit-feedback-data-driven-deferred]]

### 설계 의도 — 스텔라 블레이드식 비대칭
경직(stagger)은 **적 전용**. 플레이어는 경직 없음. 비대칭이 "내가 압박한다"는 손맛을 만든다. 경직 차단 태그도 적 GA에만 건다.

### 구현
- **히트 피드백을 GE에서 분리** — victim별 `Event.Combat.Hit` 핸들러 + 보편 HitStop(`OnWeaponHit`). 경직 중에도 칩 피드백은 들어가되 처형 강공만 제외.
- **히트스탑** — `Montage_Pause` + 타이머 `Resume`(attacker 0.08s / victim 0.12s). base GA에 있어 콤보·공중콤보가 상속으로 공짜.
- **본 셰이크 / 버텍스 셰이크** — victim 전용 연출, 이음새(`TriggerBoneShakeParams`)는 이미 뚫어둠. 데이터 전환은 hit 프로파일 3개+ 모일 때까지 보류(YAGNI).

## 6. God-class 리팩토링 — 컴포넌트 분리

> [[code-review-refactor-backlog-2026-05-27]]

### 문제
`KDEnemyBaseCharacter`가 417줄로 비대해짐(경직 상태머신 + 처형 사이클 + 사망 + 넉백 + AI 스탯). CLAUDE.md §1 "슈퍼 싱글톤 방지: Pawn 500줄 초과 금지".

### 해결
- **`UStaggerComponent`** — 경직 상태머신, 3초 자동복귀 타이머
- **`UExecutionComponent`** — 처형 사이클
- **`UExecutionProfile`** (DataAsset) — Montage/DamageGE/Cue/Duration/bSurvivable
- 통신 = `State.Combat.Staggered` 태그 + 델리게이트(OnStaggerBegin/Recovered/ExecutionBegin/Resolved), **직접 포인터 0개**(§1-3 단방향 의존성)
- 417 → ~290줄. 런타임 검증(경직→처형→복귀 / 3초 자동복귀 / 사망)까지 완료

## 7. 에디터 자동화 도구 (생산성)

> [[ue-mcp-server]] · [[ue-asset-gen-pilot]]

- **ue-mcp** (자작 MCP 서버) — `execute_python`으로 에디터를 코드에서 제어, 라이브 검증. 적 DataAsset 1클릭 생성(DA_Sword/Arrow/Bandit·Axe_Elite) — p4 add까지 자동, 검증 3/3.
- **확장 원칙** — 실제 불편한 것만 큐레이트(YAGNI). GA 블루프린트 자동화는 "손이 더 빠르다" 판단으로 전면 컷 → 자동화 욕심을 절제한 판단도 기록.

## 부록 — 적 로스터(구현됨)와 담당 매핑

| 적 | 역할(카운터플레이) | 내가 구현한 시스템 |
|---|---|---|
| 검사 도적 (잡몹) | 기본 근접, 공격 변형 다수 | WeaponTrace, 공유 BT, 경직/처형 |
| 활잡이 도적 (잡몹) | 간격 강제 → 거리 좁히기 학습 | 조준/궤적, kiting 3밴드, 평상시 자세 게이트 |
| 도끼 도적 (엘리트) | 패링 듀얼(빨강=치명/노랑=언블록) | 윈도우별 트레이스 오버라이드, Rush 모션워핑, 적 패링 |

> 잡몹 4종째 추가는 한계효용 0 → 금지. 레인지는 충분. 다음 마일스톤 = **보스**(쇼케이스 심장).
